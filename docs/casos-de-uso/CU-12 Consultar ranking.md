| **CU-12** | **Consultar ranking** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | Jugador | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. Al menos una ronda debe haber finalizado.  3. La partida debe encontrarse en estado RESULTADOS o FINALIZADA.  4. Los puntos de las rondas terminadas deben estar calculados.  5. El usuario debe tener una credencial válida.  6. El usuario debe pertenecer a la partida.  7. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Mostrar la clasificación acumulada de la partida.  2. Ordenar a los jugadores por su puntuación total.  3. Mostrar la posición de cada participante.  4. Mostrar empates de manera justa.  5. Proporcionar un ranking provisional después de cada ronda.  6. Proporcionar un ranking final cuando termine la partida.  7. Mantener el cálculo del ranking bajo responsabilidad del servidor. |
| **Descripción** | Este caso de uso permite que el anfitrión y los jugadores consulten la clasificación acumulada de la partida.  El servidor obtiene las puntuaciones de las rondas finalizadas, calcula el total de cada jugador y ordena la clasificación de mayor a menor.  Los jugadores con la misma cantidad de puntos comparten la misma posición. No se utilizará un criterio adicional para declarar ganador a uno de los jugadores empatados.  El ranking será provisional mientras queden rondas pendientes y final cuando la partida se encuentre en estado FINALIZADA. |
| **Entradas** | Entradas obtenidas de la sesión:  - Identificador de la partida.  - Credencial privada del anfitrión o jugador.  - Rol del usuario.  Entradas internas del sistema:  - Estado actual de la partida.  - Jugadores registrados.  - Resultados de las rondas finalizadas.  - Puntos obtenidos por jugador en cada ronda.  - Puntuación acumulada.  - Número de rondas completadas.  - Cantidad total de rondas.  Disparador:  El caso de uso comienza cuando el usuario accede a la sección de clasificación o cuando la aplicación muestra el ranking después de una ronda o al finalizar la partida. |
| **Secuencia normal** | 1. El anfitrión o jugador accede a la pantalla de resultados.  2. La aplicación obtiene el identificador de la partida.  3. La aplicación obtiene la credencial almacenada.  4. La aplicación envía al servidor una solicitud para consultar el ranking.  5. El servidor localiza la partida.  6. El servidor valida la credencial recibida.  7. El servidor comprueba que el usuario pertenezca a la partida.  8. El servidor consulta el estado actual de la partida.  9. El servidor comprueba que exista al menos una ronda finalizada.  10. El servidor obtiene la lista de jugadores registrados.  11. El servidor obtiene los puntos de cada ronda finalizada.  12. El servidor calcula la puntuación acumulada de cada jugador.  13. El servidor ordena a los jugadores de mayor a menor puntuación.  14. El servidor asigna la primera posición al jugador con mayor puntuación.  15. El servidor asigna posiciones a los demás jugadores.  16. El servidor identifica a los jugadores que tienen la misma puntuación.  17. El servidor asigna la misma posición a los jugadores empatados.  18. El servidor determina si el ranking es provisional o final.  19. El servidor devuelve la clasificación.  20. La aplicación recibe la información del ranking.  21. La aplicación muestra la posición de cada jugador.  22. La aplicación muestra el nombre de cada jugador.  23. La aplicación muestra la puntuación acumulada de cada jugador.  24. La aplicación identifica visualmente al jugador que está consultando.  25. La aplicación indica si el ranking es provisional o final.  26. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. Todos los jugadores tienen cero puntos  1. En el paso 12, el servidor determina que todos tienen cero puntos.  2. El servidor mantiene a todos los jugadores en el ranking.  3. El servidor asigna la misma posición a todos.  4. La aplicación muestra el empate.  5. Ningún jugador se declara como ganador único.  A2. Dos o más jugadores tienen la misma puntuación  1. En el paso 16, el servidor encuentra puntuaciones iguales.  2. El servidor asigna la misma posición a los jugadores empatados.  3. El empate no se resuelve por orden de respuesta.  4. El empate no se resuelve por orden de ingreso.  5. El empate no se resuelve alfabéticamente.  6. La aplicación muestra claramente la posición compartida.  A3. Un jugador no respondió una ronda  1. El servidor encuentra cero puntos para ese jugador en la ronda.  2. El servidor incluye al jugador en el cálculo acumulado.  3. El jugador conserva los puntos obtenidos en rondas anteriores.  4. El jugador permanece visible en el ranking.  A4. Un jugador no respondió ninguna ronda  1. El servidor determina que el jugador tiene cero puntos acumulados.  2. El servidor mantiene al jugador en el ranking.  3. La aplicación muestra su puntuación total en cero.  4. El jugador comparte posición con otros participantes que tengan cero puntos.  A5. El ranking es provisional  1. En el paso 18, el servidor detecta que todavía quedan rondas pendientes.  2. El servidor marca la clasificación como provisional.  3. La aplicación muestra el texto “Ranking provisional”.  4. Los puntos podrán cambiar después de las siguientes rondas.  A6. El ranking es final  1. En el paso 18, el servidor detecta que la partida está FINALIZADA.  2. El servidor marca la clasificación como final.  3. La aplicación muestra el texto “Ranking final”.  4. La aplicación destaca la primera posición.  5. No se aceptan nuevas puntuaciones.  A7. Todavía no finalizó ninguna ronda  1. En el paso 9, el servidor determina que no existen rondas finalizadas.  2. El servidor indica que el ranking todavía no está disponible.  3. La aplicación no muestra una clasificación.  4. El usuario permanece en la pantalla actual.  A8. Los resultados todavía están siendo calculados  1. En el paso 11, el servidor detecta que los resultados de la ronda no están completos.  2. El servidor no entrega un ranking parcial.  3. La aplicación muestra un mensaje de espera.  4. La aplicación intenta consultar nuevamente.  A9. La credencial no es válida  1. En el paso 6, el servidor no reconoce la credencial.  2. El servidor rechaza la solicitud.  3. La aplicación elimina la sesión inválida.  4. El sistema informa que no fue posible validar la sesión.  5. El usuario es dirigido a la pantalla principal.  A10. El usuario no pertenece a la partida  1. En el paso 7, el servidor determina que el usuario pertenece a otra partida.  2. El servidor rechaza la consulta.  3. El servidor no devuelve el ranking.  4. El sistema informa que el usuario no tiene acceso.  A11. La partida no existe o expiró  1. En el paso 5, el servidor no encuentra la partida.  2. El servidor rechaza la consulta.  3. La aplicación elimina la información local asociada.  4. El sistema informa que la partida ya no está disponible.  5. El usuario es dirigido a la pantalla principal.  A12. No se puede contactar con el servidor  1. En el paso 4, la aplicación no logra comunicarse con la API.  2. La aplicación conserva la sesión.  3. La aplicación no calcula el ranking localmente.  4. El sistema muestra un aviso de conexión.  5. La aplicación intenta realizar la consulta nuevamente.  A13. El estado cambia mientras se consulta el ranking  1. El servidor detecta que la partida avanzó a una nueva ronda.  2. El servidor devuelve el estado actualizado.  3. La aplicación conserva el último ranking confirmado.  4. La aplicación dirige al usuario a la ronda activa.  5. El ranking se actualizará después de finalizar la nueva ronda. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. La credencial del usuario es obligatoria.  3. La partida debe existir.  4. La credencial debe ser válida.  5. El usuario debe pertenecer a la partida.  6. Debe existir al menos una ronda finalizada.  7. Solo deben utilizarse puntos calculados por el servidor.  8. Los puntos de rondas activas no deben incluirse.  9. La puntuación acumulada debe ser la suma de los puntos válidos.  10. La puntuación total no puede ser negativa.  11. El ranking debe ordenarse de mayor a menor puntuación.  12. Todos los jugadores registrados deben aparecer en el ranking.  13. Los jugadores sin respuesta deben permanecer en la clasificación.  14. Los jugadores empatados deben compartir posición.  15. Un empate no debe resolverse con un criterio no aprobado.  16. El cliente no debe enviar ni modificar puntuaciones.  17. El cliente no debe calcular el ranking como fuente oficial.  18. El ranking debe marcarse como provisional mientras queden rondas.  19. El ranking debe marcarse como final cuando la partida termine.  20. Una falla de conexión no debe eliminar la sesión.  21. Una respuesta desactualizada no debe reemplazar un ranking más reciente.  22. La información debe pertenecer únicamente a la partida consultada. |
| **Mensajes del sistema** | 1. Ranking provisional: “Clasificación provisional”.  2. Ranking final: “Clasificación final”.  3. Empate: “Los jugadores comparten la misma posición”.  4. Sin puntos: “Todavía no se han obtenido puntos”.  5. Ranking no disponible: “El ranking estará disponible después de finalizar una ronda”.  6. Calculando ranking: “Actualizando la clasificación”.  7. Partida actualizada: “La partida avanzó a una nueva ronda”.  8. Sesión inválida: “No fue posible validar tu sesión”.  9. Sin autorización: “No tienes acceso a esta clasificación”.  10. Partida no disponible: “La partida ya no está disponible”.  11. Error de comunicación: “No fue posible obtener el ranking”. |
| **Salida del sistema** | 1. Lista de jugadores clasificada.  2. Posición asignada a cada jugador.  3. Nombre visible de cada jugador.  4. Puntuación acumulada de cada jugador.  5. Empates representados mediante posiciones compartidas.  6. Jugador actual identificado visualmente.  7. Cantidad de rondas completadas.  8. Ranking identificado como provisional o final.  9. Clasificación calculada por el servidor.  10. Jugadores sin puntos conservados en el ranking. |
