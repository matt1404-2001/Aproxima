| **CU-03** | **Recuperar sesión** |
| **Fecha de creación** | 26/09/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | Jugador | Sistema |
| **Requisitos previos** | 1. El anfitrión o jugador debe haber ingresado anteriormente a una partida. 2. El navegador debe conservar una credencial privada de anfitrión o jugador. 3. La credencial debe estar asociada con una partida existente. 4. La API y la base de datos deben estar disponibles. 5. La información de la partida no debe haber sido eliminada por la política de expiración. |
| **Objetivos asociados** | 1. Permitir que un anfitrión o jugador continúe después de recargar la página. 2. Recuperar la identidad sin solicitar una cuenta o contraseña. 3. Evitar que la recarga cree un jugador o una partida nueva. 4. Consultar el estado actual de la partida. 5. Dirigir al usuario a la pantalla correspondiente según su rol y el estado de la partida. 6. Restablecer la consulta periódica del estado. |
| **Descripción** | Este caso de uso permite recuperar la sesión de un anfitrión o jugador después de recargar la página, cerrar accidentalmente la pestaña o regresar posteriormente desde el mismo navegador.  La aplicación consulta la información almacenada localmente y envía la credencial privada al servidor. El servidor valida la credencial, identifica al usuario y devuelve el estado actual de la partida.  La recuperación no crea una nueva partida ni un nuevo jugador. Tampoco permite recuperar una sesión utilizando solamente el código de partida o el nombre del participante. |
| **Entradas** | **Entradas obtenidas del navegador:**   1. Credencial privada almacenada. 2. Identificador de la partida. 3. Rol asociado con la sesión: anfitrión o jugador.   **Entradas internas del sistema:**   1. Partidas existentes. 2. Credenciales registradas. 3. Jugadores registrados. 4. Estado actual de la partida. 5. Ronda vigente, si corresponde. 6. Fecha y hora actual del servidor.   **Disparador:**   1. El caso de uso comienza cuando el usuario abre o recarga la aplicación y existe información de sesión almacenada en el navegador. |
| **Secuencia normal** | 1. El anfitrión o jugador abre o recarga la aplicación. 2. La aplicación consulta el almacenamiento local del navegador. 3. La aplicación encuentra una credencial y un identificador de partida. 4. La aplicación identifica si la credencial corresponde a un anfitrión o jugador. 5. La aplicación envía al servidor una solicitud para recuperar la sesión. 6. La solicitud incluye la credencial privada y el identificador de la partida. 7. El servidor localiza la partida correspondiente. 8. El servidor comprueba que la partida continúe disponible. 9. El servidor valida la credencial recibida. 10. El servidor identifica al anfitrión o jugador asociado con la credencial. 11. El servidor consulta el estado actual de la partida. 12. Si el usuario es un jugador, el servidor obtiene su nombre y participación. 13. El servidor devuelve:  * rol recuperado; * información pública de la partida; * estado actual; * ronda vigente, cuando corresponda; * información del jugador, si aplica.  1. La aplicación conserva la credencial existente. 2. La aplicación actualiza su estado utilizando la información del servidor. 3. La aplicación dirige al usuario a la pantalla correspondiente:  * lobby, si la partida está esperando; * ronda activa, si existe una ronda en curso; * resultados, si la ronda terminó; * ranking final, si la partida finalizó.  1. La aplicación restablece la consulta periódica del estado de la partida. 2. El sistema informa que la sesión fue recuperada. 3. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. No existe una sesión almacenada   1. 1. En el paso 2, la aplicación no encuentra una credencial. 2. 2. La aplicación no envía una solicitud al servidor. 3. 3. El sistema muestra la pantalla principal. 4. 4. El usuario puede crear o ingresar a una partida.   A2. La información almacenada está incompleta   1. 1. En el paso 3, la aplicación encuentra una credencial sin identificador de partida o rol asociado. 2. 2. La aplicación considera inválida la información local. 3. 3. La aplicación elimina los datos incompletos. 4. 4. El sistema muestra la pantalla principal.   A3. La partida no existe o expiró   1. 1. En el paso 7, el servidor no encuentra la partida. 2. 2. El servidor rechaza la recuperación. 3. 3. La aplicación elimina la información local relacionada con esa partida. 4. 4. El sistema informa que la partida ya no está disponible. 5. 5. El usuario es dirigido a la pantalla principal.   A4. La credencial no es válida   1. 1. En el paso 9, el servidor determina que la credencial no corresponde a la partida. 2. 2. El servidor rechaza la recuperación. 3. 3. La aplicación elimina la credencial inválida. 4. 4. El sistema informa que no fue posible recuperar la sesión. 5. 5. El usuario es dirigido a la pantalla principal.   A5. La credencial del jugador no tiene una participación asociada   1. 1. En el paso 10, el servidor valida el formato de la credencial, pero no encuentra un jugador asociado. 2. 2. El servidor rechaza la recuperación. 3. 3. La aplicación elimina los datos locales de la sesión. 4. 4. El sistema informa que la sesión del jugador ya no es válida.   A6. La partida ya finalizó   1. 1. En el paso 11, el servidor detecta que la partida está FINALIZADA. 2. 2. El servidor devuelve el estado final y el ranking, si la partida todavía se conserva. 3. 3. La aplicación dirige al usuario a la pantalla de ranking final. 4. 4. No se reactivan formularios ni controles de juego.   A7. No se puede contactar con el servidor   1. 1. En el paso 5, la aplicación no logra comunicarse con la API. 2. 2. La aplicación conserva la credencial local. 3. 3. El sistema informa que no fue posible recuperar la sesión en ese momento. 4. 4. El usuario puede reintentar la operación. 5. 5. La aplicación no crea una sesión nueva.   A8. El navegador no permite consultar el almacenamiento local   1. 1. En el paso 2, la aplicación no puede acceder al almacenamiento. 2. 2. La sesión no puede recuperarse automáticamente. 3. 3. El sistema informa que el navegador debe permitir el almacenamiento local. 4. 4. El usuario permanece en la pantalla principal.   A9. El rol almacenado no coincide con la credencial   1. 1. En el paso 10, el servidor identifica un rol diferente del almacenado localmente. 2. 2. El servidor utiliza como autoridad el rol asociado con la credencial. 3. 3. La aplicación corrige la información local. 4. 4. El flujo continúa desde el paso 11. |
| **validaciones** | 1. La credencial es obligatoria para recuperar una sesión. 2. El identificador de la partida es obligatorio. 3. La partida debe existir. 4. La partida no debe haber expirado. 5. La credencial debe estar asociada con la partida indicada. 6. La credencial debe corresponder a un anfitrión o jugador registrado. 7. La recuperación no debe crear una partida nueva. 8. La recuperación no debe crear un jugador nuevo. 9. El código público no debe utilizarse como credencial. 10. El nombre del jugador no debe utilizarse para recuperar la sesión. 11. La credencial no debe incluirse en la URL. 12. La credencial no debe mostrarse en la interfaz. 13. La credencial del jugador no debe permitir ejecutar acciones del anfitrión. 14. El estado devuelto por el servidor debe considerarse la fuente oficial. 15. Un error temporal de conexión no debe eliminar la credencial almacenada. 16. Una credencial inválida o asociada con una partida inexistente debe eliminarse del navegador. 17. La respuesta correcta de una ronda activa no debe enviarse durante la recuperación. |
| **Mensaje de Sistema** | 1. Sesión recuperada: “Sesión recuperada correctamente”. 2. Sin sesión guardada: “No se encontró una sesión anterior”. 3. Información incompleta: “La información guardada no es válida”. 4. Partida no disponible: “La partida ya no está disponible”. 5. Credencial inválida: “No fue posible recuperar la sesión”. 6. Participación no encontrada: “La sesión del jugador ya no es válida”. 7. Partida finalizada: “Esta partida ya finalizó”. 8. Error de comunicación: “No fue posible comunicarse con el servidor. Inténtalo nuevamente”. 9. Almacenamiento no disponible: “El navegador debe permitir el almacenamiento local para recuperar tu sesión”. |
| **Salida de Sistema** | 1. Identidad del anfitrión o jugador recuperada. 2. Rol del usuario confirmado por el servidor. 3. Partida asociada con la sesión. 4. Información pública de la partida actualizada. 5. Estado actual de la partida recuperado. 6. Información del jugador recuperada, cuando corresponda. 7. Pantalla correspondiente al estado actual mostrada. 8. Consulta periódica del estado restablecida. 9. Credencial privada conservada en el navegador. 10. Ninguna partida o participación nueva creada. |
