| **CU-09** | **Cerrar ronda** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Sistema | Jugador |
| **Requisitos previos** | 1. La partida debe existir.  2. La partida debe encontrarse en estado RONDA\_ACTIVA.  3. Debe existir una ronda vigente.  4. La ronda debe tener una hora oficial de finalización.  5. La ronda debe tener un desafío y una respuesta correcta asociados.  6. Debe cumplirse al menos una condición de cierre.  7. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Finalizar la recepción de estimaciones.  2. Cerrar la ronda cuando termine el tiempo.  3. Cerrar anticipadamente cuando todos respondan.  4. Rechazar respuestas recibidas fuera de tiempo.  5. Calcular los resultados individuales.  6. Calcular las estadísticas de la ronda.  7. Actualizar las puntuaciones acumuladas.  8. Cambiar la partida al estado RESULTADOS.  9. Mantener el avance a la siguiente ronda bajo control del anfitrión. |
| **Descripción** | Este caso de uso permite que el servidor cierre una ronda cuando se alcanza la hora oficial de finalización o cuando todos los jugadores registrados han enviado una estimación válida.  El cierre impide aceptar nuevas respuestas, permite revelar la respuesta correcta y prepara los resultados individuales, las estadísticas colectivas y el ranking acumulado.  La ronda puede cerrarse durante una consulta de estado o inmediatamente después de registrar la última estimación necesaria. El cierre no inicia automáticamente la siguiente ronda.  La fórmula exacta de puntuación deberá encontrarse definida antes de implementar este caso de uso. |
| **Entradas** | Entradas provenientes de la ronda:  - Identificador de la partida.  - Identificador de la ronda vigente.  - Hora oficial de inicio.  - Hora oficial de finalización.  - Desafío asociado.  - Respuesta correcta.  Entradas provenientes de los jugadores:  - Estimaciones válidas registradas.  - Hora oficial de recepción de cada estimación.  - Jugadores que no respondieron.  Entradas internas del sistema:  - Hora actual del servidor.  - Cantidad total de jugadores.  - Cantidad de jugadores que respondieron.  - Fórmula de puntuación aprobada.  - Puntuaciones acumuladas de los jugadores.  Disparador:  El caso de uso comienza cuando el servidor detecta que terminó el tiempo o que todos los jugadores enviaron una estimación válida. |
| **Secuencia normal** | 1. El servidor recibe una consulta de estado o una estimación válida.  2. El servidor localiza la partida.  3. El servidor consulta la ronda vigente.  4. El servidor comprueba que la ronda se encuentre activa.  5. El servidor obtiene la hora actual.  6. El servidor obtiene la hora oficial de finalización.  7. El servidor cuenta la cantidad total de jugadores.  8. El servidor cuenta la cantidad de jugadores que respondieron.  9. El servidor verifica que se cumpla una condición de cierre.  10. El servidor inicia la operación de cierre.  11. El servidor comprueba nuevamente que la ronda continúe activa.  12. El servidor impide la aceptación de nuevas estimaciones.  13. El servidor obtiene la respuesta correcta del desafío.  14. El servidor obtiene las estimaciones válidas de la ronda.  15. El servidor identifica a los jugadores que no respondieron.  16. El servidor calcula la diferencia de cada estimación respecto a la respuesta correcta.  17. El servidor aplica la fórmula de puntuación aprobada.  18. El servidor asigna cero puntos a los jugadores que no respondieron.  19. El servidor guarda el resultado individual de cada jugador.  20. El servidor calcula la estimación mínima.  21. El servidor calcula el promedio de las estimaciones.  22. El servidor calcula la estimación máxima.  23. El servidor cuenta las estimaciones aceptadas.  24. El servidor actualiza la puntuación acumulada de cada jugador.  25. El servidor actualiza el ranking provisional.  26. El servidor marca la ronda como cerrada.  27. El servidor cambia el estado de la partida a RESULTADOS.  28. El servidor guarda los cambios de forma completa.  29. El servidor devuelve el nuevo estado de la partida.  30. Las aplicaciones detectan el estado RESULTADOS mediante polling.  31. Las aplicaciones bloquean los formularios de estimación.  32. Las aplicaciones dirigen a los usuarios a la pantalla de resultados.  33. El sistema espera que el anfitrión decida cuándo avanzar.  34. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. El tiempo todavía no terminó y faltan respuestas  1. En el paso 9, el servidor determina que no se cumple ninguna condición de cierre.  2. La ronda permanece en estado activo.  3. El servidor continúa aceptando estimaciones válidas.  4. El sistema devuelve el estado RONDA\_ACTIVA.  5. El caso de uso de cierre finaliza sin modificar la ronda.  A2. Todos respondieron antes de terminar el tiempo  1. El servidor determina que la cantidad de respuestas coincide con la cantidad de jugadores.  2. El servidor cierra la ronda anticipadamente.  3. El tiempo restante deja de ser relevante.  4. El sistema continúa desde el paso 10 de la secuencia normal.  5. La siguiente ronda no se inicia automáticamente.  A3. Terminó el tiempo y algunos jugadores no respondieron  1. El servidor detecta que se alcanzó la hora oficial de finalización.  2. El servidor cierra la ronda.  3. Los jugadores que respondieron conservan sus estimaciones.  4. Los jugadores que no respondieron reciben cero puntos.  5. El sistema continúa con el cálculo de resultados.  A4. Ningún jugador respondió  1. En el paso 14, el servidor determina que no existen estimaciones válidas.  2. El servidor asigna cero puntos a todos los jugadores.  3. El servidor no calcula mínimo, promedio ni máximo.  4. Las estadísticas quedan marcadas como “Sin respuestas”.  5. El servidor cambia la partida a RESULTADOS.  A5. Solo respondió un jugador  1. El servidor obtiene una única estimación válida.  2. El servidor calcula el resultado del jugador.  3. La estimación mínima corresponde a su respuesta.  4. El promedio corresponde a su respuesta.  5. La estimación máxima corresponde a su respuesta.  6. Los demás jugadores reciben cero puntos.  A6. Dos solicitudes intentan cerrar la ronda  1. Dos solicitudes detectan simultáneamente una condición de cierre.  2. El servidor permite que una solicitud realice el cierre.  3. La segunda solicitud detecta que la ronda ya está cerrada.  4. La segunda solicitud no vuelve a calcular ni duplicar resultados.  5. Ambas solicitudes obtienen el estado RESULTADOS.  A7. Una estimación llega durante el cierre  1. El servidor compara la hora de recepción con la hora oficial de finalización.  2. Si la estimación llegó fuera de tiempo, el servidor la rechaza.  3. Si el jugador ya tenía una estimación registrada, el servidor conserva la primera.  4. La operación de cierre utiliza únicamente estimaciones válidas.  5. La respuesta rechazada no se incluye en las estadísticas.  A8. No se pueden guardar los resultados  1. En el paso 28, ocurre un error en la base de datos.  2. El servidor cancela la operación de cálculo y persistencia.  3. No deben guardarse resultados parciales.  4. El tiempo oficial de la ronda permanece vencido.  5. El servidor deja de aceptar nuevas estimaciones.  6. El sistema informa que los resultados todavía no están disponibles.  7. Una solicitud posterior puede reintentar el cierre.  A9. La fórmula de puntuación no está disponible  1. En el paso 17, el servidor no encuentra una fórmula válida.  2. El servidor cancela el cálculo de resultados.  3. No se actualizan las puntuaciones acumuladas.  4. El servidor registra el error técnico.  5. El sistema informa que no fue posible preparar los resultados.  A10. La ronda ya estaba cerrada  1. En el paso 4, el servidor detecta que la ronda ya no está activa.  2. El servidor no vuelve a procesar los resultados.  3. El servidor devuelve el estado actual.  4. La aplicación dirige al usuario a la pantalla correspondiente.  A11. El anfitrión fuerza el cierre de la ronda  1. Esta secuencia solo aplica si se implementa la funcionalidad opcional.  2. El servidor valida la credencial del anfitrión.  3. El sistema solicita confirmación antes de continuar.  4. El servidor cierra la ronda aunque falten jugadores.  5. Los jugadores que no respondieron reciben cero puntos.  6. El sistema continúa desde el paso 10 de la secuencia normal. |
| **Validaciones** | 1. La partida debe existir.  2. La ronda debe existir.  3. La ronda debe ser la ronda vigente.  4. La partida debe encontrarse en estado RONDA\_ACTIVA.  5. La hora actual debe obtenerse del servidor.  6. La ronda debe cerrarse cuando se alcance la hora oficial de finalización.  7. La ronda debe cerrarse anticipadamente cuando todos respondan.  8. La comparación de tiempo no debe depender del navegador.  9. El cierre debe ejecutarse una sola vez.  10. El cierre debe impedir nuevas estimaciones.  11. Solo deben utilizarse estimaciones válidas y aceptadas.  12. Las estimaciones rechazadas no deben incluirse en las estadísticas.  13. Cada jugador debe tener como máximo un resultado por ronda.  14. La diferencia debe calcularse en el servidor.  15. Los puntos deben calcularse en el servidor.  16. Los puntos no pueden ser negativos.  17. Los jugadores sin respuesta deben recibir cero puntos.  18. La misma estimación debe producir la misma puntuación para el mismo desafío.  19. La estimación mínima debe utilizar únicamente respuestas válidas.  20. El promedio debe utilizar únicamente respuestas válidas.  21. La estimación máxima debe utilizar únicamente respuestas válidas.  22. Si no existen respuestas, las estadísticas deben indicar “Sin respuestas”.  23. El ranking debe actualizarse con los puntos de la ronda.  24. La respuesta correcta solo puede revelarse después del cierre.  25. La partida debe cambiar a RESULTADOS.  26. El cierre no debe iniciar automáticamente la siguiente ronda.  27. Los resultados deben guardarse completamente o cancelarse completamente.  28. Solicitudes simultáneas no deben duplicar resultados ni puntos.  29. Una falla al calcular resultados no debe reabrir el tiempo de la ronda.  30. El cierre forzado solo debe permitirse al anfitrión si se implementa la función opcional. |
| **Mensajes del sistema** | 1. Tiempo finalizado: “El tiempo de la ronda terminó”.  2. Todos respondieron: “Todos los jugadores respondieron”.  3. Ronda cerrada: “La ronda ha finalizado”.  4. Preparando resultados: “Calculando resultados”.  5. Resultados disponibles: “Los resultados de la ronda están disponibles”.  6. Sin respuestas: “Ningún jugador respondió esta ronda”.  7. Respuesta fuera de tiempo: “La estimación fue recibida fuera del tiempo permitido”.  8. Ronda ya cerrada: “La ronda ya había finalizado”.  9. Error al guardar: “No fue posible preparar los resultados”.  10. Puntuación no disponible: “No fue posible calcular las puntuaciones”.  11. Cierre anticipado: “La ronda finalizó porque todos los jugadores respondieron”.  12. Cierre forzado: “El anfitrión finalizó la ronda”. |
| **Salida del sistema** | 1. Ronda cerrada.  2. Nuevas estimaciones bloqueadas.  3. Respuesta correcta disponible.  4. Diferencia individual calculada.  5. Puntos individuales calculados.  6. Cero puntos asignados a quienes no respondieron.  7. Resultados individuales almacenados.  8. Estimación mínima calculada.  9. Promedio calculado.  10. Estimación máxima calculada.  11. Cantidad de respuestas calculada.  12. Puntuaciones acumuladas actualizadas.  13. Ranking provisional actualizado.  14. Estado de la partida cambiado a RESULTADOS.  15. Pantalla de resultados disponible.  16. Avance a la siguiente ronda pendiente de la acción del anfitrión. |
