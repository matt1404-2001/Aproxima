| **CU-07** | **Participar en una ronda** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Jugador | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. La partida debe encontrarse en estado RONDA\_ACTIVA.  3. El jugador debe estar registrado en la partida.  4. El jugador debe tener una credencial privada válida.  5. Debe existir una ronda vigente.  6. La ronda debe tener un desafío asignado.  7. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Mostrar al jugador el desafío de la ronda.  2. Informar el número de ronda y el progreso de la partida.  3. Mostrar la unidad en la que debe responder.  4. Mostrar el tiempo restante.  5. Permitir que el jugador prepare una estimación.  6. Mantener oculta la respuesta correcta.  7. Detectar el cierre de la ronda.  8. Impedir que un jugador que ya respondió vuelva a utilizar el formulario. |
| **Descripción** | Este caso de uso permite que un jugador participe en una ronda activa de Estimate Arena.  El sistema muestra el enunciado del desafío, la unidad solicitada, el número de ronda y un contador visual. El contador utiliza la hora oficial de finalización comunicada por el servidor.  Durante esta etapa, el jugador puede introducir una estimación numérica. El envío definitivo de la estimación se documenta en el caso de uso siguiente.  La respuesta correcta permanece oculta mientras la ronda esté activa. |
| **Entradas** | Entradas obtenidas de la sesión:  - Identificador de la partida.  - Credencial privada del jugador.  - Identificador del jugador.  Entradas internas del sistema:  - Estado actual de la partida.  - Número de la ronda vigente.  - Cantidad total de rondas.  - Enunciado del desafío.  - Unidad de respuesta.  - Hora actual del servidor.  - Hora oficial de finalización.  - Estado de respuesta del jugador.  Disparador:  El caso de uso comienza cuando la aplicación detecta que la partida cambió al estado RONDA\_ACTIVA. |
| **Secuencia normal** | 1. La aplicación detecta que la partida se encuentra en estado RONDA\_ACTIVA.  2. La aplicación obtiene el identificador de la partida y la credencial del jugador.  3. La aplicación solicita al servidor la información pública de la ronda vigente.  4. El servidor localiza la partida.  5. El servidor valida la credencial del jugador.  6. El servidor comprueba que el jugador pertenezca a la partida.  7. El servidor consulta la ronda vigente.  8. El servidor comprueba que la ronda continúe activa.  9. El servidor consulta si el jugador ya respondió la ronda.  10. El servidor obtiene el enunciado del desafío.  11. El servidor obtiene la unidad en la que debe expresarse la estimación.  12. El servidor obtiene el número de la ronda vigente.  13. El servidor obtiene la hora oficial de finalización.  14. El servidor obtiene la hora actual.  15. El servidor prepara la información pública de la ronda.  16. El servidor excluye la respuesta correcta.  17. El servidor devuelve la información de la ronda a la aplicación.  18. La aplicación muestra el número de ronda y el total de rondas.  19. La aplicación muestra el enunciado del desafío.  20. La aplicación muestra la unidad esperada.  21. La aplicación calcula el tiempo restante utilizando la hora del servidor y la hora de finalización.  22. La aplicación muestra el contador.  23. La aplicación muestra el campo para introducir la estimación.  24. La aplicación muestra la opción “Enviar estimación”.  25. El jugador analiza el desafío.  26. El jugador introduce un valor numérico en el formulario.  27. La aplicación mantiene actualizado el contador visual.  28. El jugador queda preparado para enviar su estimación.  29. El caso de uso finaliza cuando el jugador envía la estimación o cuando la ronda termina. |
| **Secuencias alternativas y excepciones** | A1. El jugador ya respondió  1. En el paso 9, el servidor detecta que el jugador ya tiene una estimación registrada.  2. El servidor informa que la respuesta fue enviada anteriormente.  3. La aplicación no muestra un formulario editable.  4. La aplicación muestra la estimación registrada o una confirmación de envío.  5. El jugador espera el cierre de la ronda.  A2. La ronda terminó antes de mostrar el desafío  1. En el paso 8, el servidor detecta que terminó el tiempo.  2. El servidor cierra la ronda.  3. El servidor cambia el estado a RESULTADOS.  4. El servidor no devuelve un formulario de participación.  5. La aplicación dirige al jugador a la pantalla de resultados.  A3. Todos los jugadores ya respondieron  1. El servidor detecta que todos los jugadores enviaron una estimación.  2. El servidor cierra anticipadamente la ronda.  3. El servidor cambia el estado a RESULTADOS.  4. La aplicación dirige al jugador a la pantalla de resultados.  A4. El tiempo termina mientras el jugador escribe  1. El contador visual llega a cero.  2. La aplicación deshabilita el formulario.  3. La aplicación impide nuevos intentos desde la interfaz.  4. La aplicación consulta el estado oficial de la partida.  5. El servidor confirma el cierre de la ronda.  6. La aplicación dirige al jugador a los resultados.  7. La estimación no enviada no se guarda.  A5. El jugador recarga la página  1. El navegador vuelve a cargar la aplicación.  2. La aplicación recupera la credencial almacenada.  3. La aplicación consulta el estado oficial de la partida.  4. El servidor identifica al jugador.  5. Si la ronda sigue activa, la aplicación vuelve a mostrar el desafío.  6. Si el jugador ya respondió, la aplicación mantiene el formulario bloqueado.  7. Si la ronda terminó, la aplicación muestra los resultados.  A6. La información recibida pertenece a otra ronda  1. La aplicación compara el número recibido con la ronda que está mostrando.  2. La aplicación detecta que la información no corresponde a la ronda vigente.  3. La aplicación descarta el estado anterior.  4. La aplicación solicita nuevamente el estado oficial.  5. La aplicación muestra la ronda vigente.  A7. No se puede contactar con el servidor  1. En el paso 3, la aplicación no logra comunicarse con la API.  2. La aplicación muestra un aviso de conexión.  3. La aplicación conserva temporalmente la última información válida.  4. El contador continúa como referencia visual.  5. La aplicación no considera que el tiempo se haya extendido.  6. El jugador no puede enviar una estimación mientras no exista comunicación.  7. La aplicación intenta consultar nuevamente el estado.  A8. La credencial del jugador no es válida  1. En el paso 5, el servidor no reconoce la credencial.  2. El servidor rechaza la consulta.  3. La aplicación elimina la sesión inválida.  4. El sistema informa que no fue posible validar la sesión.  5. El usuario es dirigido a la pantalla principal.  A9. El jugador no pertenece a la partida  1. En el paso 6, el servidor determina que el jugador pertenece a otra partida.  2. El servidor rechaza la consulta.  3. El servidor no envía información del desafío.  4. El sistema informa que el jugador no puede participar en esa partida.  A10. La partida finalizó  1. El servidor detecta que la partida se encuentra en estado FINALIZADA.  2. El servidor no devuelve información de una ronda activa.  3. La aplicación dirige al jugador al ranking final. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. La partida debe existir.  3. La credencial del jugador debe ser válida.  4. La credencial debe estar asociada con la partida.  5. El jugador debe estar registrado en la partida.  6. La partida debe encontrarse en estado RONDA\_ACTIVA.  7. La ronda solicitada debe ser la ronda vigente.  8. La ronda debe tener un desafío asignado.  9. El desafío debe incluir un enunciado.  10. El desafío debe indicar la unidad esperada.  11. La hora de finalización debe provenir del servidor.  12. El contador del navegador debe ser únicamente informativo.  13. La aplicación no debe modificar la hora oficial de finalización.  14. La respuesta correcta no debe enviarse durante la ronda.  15. La información explicativa del resultado no debe enviarse antes del cierre.  16. El formulario debe mostrarse únicamente si el jugador no ha respondido.  17. El formulario debe deshabilitarse cuando el contador llegue a cero.  18. El formulario debe permanecer bloqueado después de una respuesta aceptada.  19. Recargar la página no debe crear otro jugador.  20. Recargar la página no debe permitir una segunda respuesta.  21. Una falla de conexión no debe extender el tiempo de la ronda.  22. La información de una ronda anterior no debe reemplazar la ronda vigente. |
| **Mensajes del sistema** | 1. Ronda activa: “Ronda en curso”.  2. Progreso: “Ronda 1 de 5”.  3. Tiempo restante: “Tiempo restante: 30 segundos”.  4. Unidad esperada: “Ingresa tu estimación en la unidad indicada”.  5. Respuesta registrada: “Ya enviaste una estimación para esta ronda”.  6. Tiempo finalizado: “El tiempo de la ronda terminó”.  7. Todos respondieron: “Todos los jugadores respondieron”.  8. Esperando resultados: “Esperando los resultados de la ronda”.  9. Error de comunicación: “Se perdió la conexión con el servidor”.  10. Sesión inválida: “No fue posible validar tu sesión”.  11. Ronda no disponible: “La ronda ya no está disponible”.  12. Partida finalizada: “La partida ha finalizado”. |
| **Salida del sistema** | 1. Ronda vigente identificada.  2. Número de ronda mostrado.  3. Cantidad total de rondas mostrada.  4. Enunciado del desafío mostrado.  5. Unidad de respuesta mostrada.  6. Hora oficial de finalización recibida.  7. Contador visual iniciado.  8. Formulario de estimación habilitado cuando corresponde.  9. Estado de respuesta del jugador identificado.  10. Respuesta correcta mantenida oculta.  11. Polling de la partida activo.  12. Jugador preparado para enviar su estimación. |
