| **CU-08** | **Enviar estimación** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Jugador | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. La partida debe encontrarse en estado RONDA\_ACTIVA.  3. El jugador debe estar registrado en la partida.  4. El jugador debe tener una credencial privada válida.  5. Debe existir una ronda vigente.  6. El jugador no debe haber respondido la ronda.  7. La hora límite de la ronda no debe haberse alcanzado.  8. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Permitir que el jugador envíe una estimación numérica.  2. Validar que la estimación corresponda a la ronda vigente.  3. Verificar que la respuesta llegue dentro del tiempo permitido.  4. Impedir respuestas duplicadas.  5. Registrar la hora de recepción del servidor.  6. Conservar la estimación para calcular posteriormente el resultado.  7. Cerrar anticipadamente la ronda cuando todos hayan respondido. |
| **Descripción** | Este caso de uso permite que un jugador envíe una estimación numérica durante una ronda activa.  La aplicación realiza validaciones básicas antes de enviar la solicitud. El servidor realiza las validaciones definitivas relacionadas con la identidad del jugador, el estado de la partida, la ronda vigente, el tiempo disponible y la existencia de una respuesta anterior.  Si la estimación es válida, el servidor la guarda junto con la hora oficial de recepción. La estimación queda confirmada y no puede modificarse ni reemplazarse.  La aceptación de la respuesta no depende del contador del navegador, sino de la hora en que el servidor recibe la solicitud. |
| **Entradas** | Entradas proporcionadas por el jugador:  - Valor numérico de la estimación.  - Selección de la opción “Enviar estimación”.  Entradas obtenidas de la sesión:  - Identificador de la partida.  - Identificador de la ronda.  - Credencial privada del jugador.  Entradas internas del sistema:  - Estado actual de la partida.  - Ronda vigente.  - Hora actual del servidor.  - Hora oficial de finalización.  - Estimaciones registradas en la ronda.  - Cantidad total de jugadores.  - Cantidad de jugadores que respondieron.  Disparador:  El caso de uso comienza cuando el jugador introduce un valor y selecciona la opción “Enviar estimación”. |
| **Secuencia normal** | 1. El jugador visualiza el desafío de la ronda activa.  2. El jugador introduce una estimación en el formulario.  3. La aplicación elimina los espacios innecesarios del valor introducido.  4. La aplicación comprueba que el campo no esté vacío.  5. La aplicación comprueba que el valor sea un número entero positivo.  6. El jugador selecciona la opción “Enviar estimación”.  7. La aplicación deshabilita temporalmente el botón de envío.  8. La aplicación obtiene el identificador de la partida.  9. La aplicación obtiene el identificador de la ronda vigente.  10. La aplicación obtiene la credencial privada del jugador.  11. La aplicación envía la solicitud al servidor.  12. El servidor localiza la partida.  13. El servidor valida la credencial del jugador.  14. El servidor comprueba que el jugador pertenezca a la partida.  15. El servidor consulta el estado actual de la partida.  16. El servidor comprueba que la partida se encuentre en estado RONDA\_ACTIVA.  17. El servidor identifica la ronda vigente.  18. El servidor comprueba que la ronda enviada coincida con la ronda vigente.  19. El servidor obtiene la hora actual.  20. El servidor compara la hora actual con la hora oficial de finalización.  21. El servidor comprueba que el jugador no haya respondido anteriormente.  22. El servidor valida que la estimación sea un número entero positivo.  23. El servidor registra la estimación.  24. El servidor registra la hora oficial de recepción.  25. El servidor guarda la estimación en la base de datos.  26. El servidor cuenta cuántos jugadores respondieron.  27. El servidor determina si todavía faltan jugadores por responder.  28. El servidor devuelve la confirmación de la estimación.  29. La aplicación informa que la respuesta fue registrada.  30. La aplicación mantiene bloqueado el formulario.  31. La aplicación impide que el jugador envíe otra estimación.  32. El jugador permanece esperando el cierre de la ronda.  33. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. El campo está vacío  1. En el paso 4, la aplicación detecta que no se introdujo una estimación.  2. La aplicación no envía la solicitud.  3. El sistema señala el campo obligatorio.  4. El jugador permanece en el formulario.  A2. La estimación no es un número válido  1. En el paso 5, la aplicación detecta texto o un valor no numérico.  2. La aplicación no envía la solicitud.  3. El sistema informa que debe introducirse un número entero positivo.  4. El jugador puede corregir el valor.  A3. La estimación es decimal, negativa o igual a cero  1. En el paso 5, la aplicación detecta un valor no permitido.  2. La aplicación no envía la solicitud.  3. El sistema informa que la estimación debe ser un número entero mayor que cero.  4. El jugador puede corregir el valor.  A4. La credencial del jugador no es válida  1. En el paso 13, el servidor no reconoce la credencial.  2. El servidor rechaza la estimación.  3. La estimación no se guarda.  4. La aplicación elimina la sesión inválida.  5. El sistema informa que no fue posible validar al jugador.  A5. El jugador no pertenece a la partida  1. En el paso 14, el servidor determina que el jugador pertenece a otra partida.  2. El servidor rechaza la estimación.  3. La estimación no se guarda.  4. El sistema informa que el jugador no puede responder en esa partida.  A6. La ronda enviada no es la ronda vigente  1. En el paso 18, el servidor detecta que la solicitud corresponde a otra ronda.  2. El servidor rechaza la estimación.  3. La estimación no se guarda.  4. El servidor devuelve el estado y la ronda actual.  5. La aplicación actualiza la pantalla.  A7. El tiempo terminó antes de recibir la estimación  1. En el paso 20, el servidor determina que se alcanzó la hora límite.  2. El servidor rechaza la estimación.  3. La estimación no se guarda.  4. El servidor inicia o confirma el cierre de la ronda.  5. El sistema informa que el tiempo terminó.  6. La aplicación bloquea el formulario.  7. La aplicación dirige al jugador a los resultados cuando estén disponibles.  A8. El jugador ya respondió  1. En el paso 21, el servidor encuentra una estimación registrada.  2. El servidor rechaza el nuevo envío.  3. El servidor conserva la primera estimación.  4. El sistema informa que el jugador ya respondió.  5. La aplicación bloquea el formulario.  A9. El jugador envía desde dos pestañas  1. Dos solicitudes del mismo jugador llegan casi simultáneamente.  2. El servidor procesa una de las solicitudes.  3. El servidor registra una única estimación.  4. El servidor rechaza la otra solicitud como duplicada.  5. La primera estimación aceptada permanece como respuesta definitiva.  A10. Todos los jugadores respondieron  1. En el paso 27, el servidor determina que todos los jugadores respondieron.  2. El servidor cierra anticipadamente la ronda.  3. El servidor deja de aceptar nuevas estimaciones.  4. El servidor cambia el estado a RESULTADOS.  5. El servidor calcula los resultados correspondientes.  6. La aplicación dirige al jugador a la pantalla de resultados.  7. La siguiente ronda no se inicia automáticamente.  A11. No se puede guardar la estimación  1. En el paso 25, ocurre un error en la base de datos.  2. El servidor cancela el registro.  3. La estimación no se considera aceptada.  4. El sistema informa que no fue posible guardar la respuesta.  5. La aplicación vuelve a habilitar el formulario si todavía queda tiempo.  A12. No se puede contactar con el servidor  1. En el paso 11, la aplicación no logra comunicarse con la API.  2. La aplicación no considera la estimación como aceptada.  3. La aplicación muestra un error de conexión.  4. La aplicación consulta el estado oficial antes de permitir otro intento.  5. Si no existe una estimación registrada y queda tiempo, el jugador puede reintentar.  6. Si la estimación ya fue registrada, la aplicación bloquea el formulario.  A13. La respuesta del servidor se pierde después de guardar  1. El servidor guarda la estimación, pero la aplicación no recibe la confirmación.  2. La aplicación muestra un aviso de conexión.  3. La aplicación consulta el estado del jugador en la ronda.  4. El servidor informa que ya existe una estimación registrada.  5. La aplicación muestra la confirmación.  6. La aplicación bloquea el formulario. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. El identificador de la ronda es obligatorio.  3. La credencial del jugador es obligatoria.  4. La partida debe existir.  5. La credencial debe ser válida.  6. El jugador debe pertenecer a la partida.  7. La partida debe encontrarse en estado RONDA\_ACTIVA.  8. La ronda enviada debe coincidir con la ronda vigente.  9. La hora actual del servidor debe ser anterior a la hora oficial de finalización.  10. El contador del navegador no debe decidir si la respuesta es aceptada.  11. La estimación es obligatoria.  12. La estimación debe ser un número entero.  13. La estimación debe ser mayor que cero.  14. La estimación debe encontrarse dentro del rango numérico admitido.  15. El jugador solo puede registrar una estimación por ronda.  16. La estimación aceptada no puede modificarse.  17. La estimación aceptada no puede eliminarse durante la partida.  18. La hora de recepción debe generarse en el servidor.  19. Un envío duplicado no debe crear varios registros.  20. Solicitudes simultáneas deben producir como máximo una estimación válida.  21. El registro debe guardarse completamente o cancelarse completamente.  22. La confirmación no debe revelar la respuesta correcta.  23. La confirmación no debe calcular ni mostrar puntos antes del cierre.  24. El anfitrión no puede enviar estimaciones si no está registrado como jugador.  25. Si todos respondieron, la ronda debe pasar a RESULTADOS.  26. El cierre anticipado no debe iniciar automáticamente la siguiente ronda. |
| **Mensajes del sistema** | 1. Estimación registrada: “Tu estimación fue registrada correctamente”.  2. Campo obligatorio: “Ingresa una estimación antes de continuar”.  3. Valor inválido: “La estimación debe ser un número entero mayor que cero”.  4. Sesión inválida: “No fue posible validar tu sesión”.  5. Jugador no autorizado: “No puedes responder en esta partida”.  6. Ronda incorrecta: “La ronda cambió. Actualizando la información”.  7. Tiempo finalizado: “El tiempo terminó. Tu estimación no fue registrada”.  8. Respuesta duplicada: “Ya enviaste una estimación para esta ronda”.  9. Error al guardar: “No fue posible guardar tu estimación”.  10. Error de comunicación: “No fue posible comunicarse con el servidor”.  11. Verificando respuesta: “Verificando si tu estimación fue registrada”.  12. Todos respondieron: “Todos los jugadores respondieron. Mostrando resultados”. |
| **Salida del sistema** | 1. Identidad del jugador validada.  2. Partida y ronda verificadas.  3. Tiempo disponible comprobado por el servidor.  4. Estimación válida registrada.  5. Hora oficial de recepción almacenada.  6. Primera estimación conservada como respuesta definitiva.  7. Formulario de respuesta bloqueado.  8. Confirmación mostrada al jugador.  9. Cantidad de respuestas actualizada.  10. Cierre anticipado iniciado cuando todos respondieron.  11. Respuesta correcta mantenida oculta mientras la ronda continúe activa. |
