| **CU-01** | **Crear partida** |
| **Fecha de creación** | 26/09/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | sistema |
| **Requisitos previos** | 1. El anfitrión debe tener acceso a la aplicación web. 2. La API y la base de datos deben estar disponibles. 3. Deben existir al menos cinco desafíos activos y disponibles en el sistema. 4. El navegador debe permitir almacenar localmente la credencial del anfitrión. 5. El anfitrión no necesita disponer de una cuenta ni iniciar sesión. |
| **Objetivos asociados** | 1. Permitir que una persona organice una nueva partida. 2. Generar un código público para que los jugadores puedan ingresar. 3. Generar una credencial privada que identifique al anfitrión. 4. Preparar las cinco rondas que formarán parte de la partida. 5. Crear el lobby inicial en el que se recibirán los jugadores. |
| **Descripción** | permitir que una persona cree una nueva partida de Estimate Arena y se convierta en su anfitrión.  El anfitrión no necesita registrarse ni proporcionar información personal. Al solicitar la creación, el sistema genera un código público de sala y una credencial privada de anfitrión.  El código público podrá compartirse con los jugadores. La credencial privada permitirá controlar posteriormente la partida, incluyendo iniciarla, avanzar entre rondas y finalizarla.  El sistema también selecciona cinco desafíos activos sin repetirlos, define su orden y deja la partida en estado LOBBY, lista para recibir jugadores. |
| **Entradas** | **Entrada proporcionada por el anfitrión**   * Selección de la opción **“Crear partida”**.   El anfitrión no deberá introducir nombre, contraseña, duración ni cantidad de rondas.  **Entradas internas del sistema**   * Cantidad de rondas configurada: 5. * Duración máxima de cada ronda: 30 segundos. * Cantidad máxima de jugadores: 40. * Conjunto de desafíos activos disponibles. * Fecha y hora actual del servidor.   **Disparador**  El caso de uso comienza cuando el anfitrión selecciona la opción “Crear partida” desde la pantalla principal. |
| **Secuencia normal** | 1. El anfitrión accede a la pantalla principal de Estimate Arena. 2. El sistema muestra las opciones “Crear partida” e “Ingresar a partida”. 3. El anfitrión selecciona “Crear partida”. 4. La aplicación comprueba que puede conservar localmente la credencial del anfitrión. 5. La aplicación envía al servidor una solicitud para crear la partida. 6. El servidor verifica que existan al menos cinco desafíos activos. 7. El servidor genera un código público de partida. 8. El servidor comprueba que el código no esté siendo utilizado por otra partida activa. 9. El servidor genera una credencial privada y segura para el anfitrión. 10. El servidor selecciona cinco desafíos activos sin repetirlos. 11. El servidor establece el orden en que se utilizarán los desafíos. 12. El servidor crea la partida con estado LOBBY. 13. El servidor registra la configuración de la partida:  * cinco rondas; * treinta segundos por ronda; * máximo de cuarenta jugadores.  1. • El servidor guarda la partida y sus desafíos asignados. 2. • El servidor devuelve a la aplicación:  * identificador de la partida; * código público; * estado inicial; * credencial privada del anfitrión.  1. La aplicación almacena localmente la credencial del anfitrión. 2. La aplicación dirige al anfitrión al lobby. 3. El sistema muestra el código de la partida y la lista vacía de participantes. 4. El sistema muestra una opción para copiar el código y compartirlo con los jugadores. 5. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | **A1. No existen suficientes desafíos**   1. En el paso 6, el servidor detecta que existen menos de cinco desafíos activos. 2. El servidor cancela la operación. 3. No se crea ninguna partida. 4. El sistema muestra un mensaje indicando que no hay suficientes desafíos disponibles. 5. El anfitrión permanece en la pantalla principal.   **A2. El código generado ya está en uso**   1. En el paso 8, el servidor detecta que el código pertenece a otra partida activa. 2. El servidor descarta el código. 3. El servidor genera otro código. 4. El flujo continúa desde el paso 8.   Esta situación debe resolverse internamente y normalmente no debe mostrarse al anfitrión.  **A3. No se puede guardar la partida**   1. En el paso 14, ocurre un error al guardar la información. 2. El sistema cancela la creación completa. 3. No debe quedar una partida parcialmente creada. 4. El sistema informa al anfitrión que no fue posible crear la partida. 5. El anfitrión puede intentar nuevamente.   **A4. No se puede contactar con el servidor**   1. En el paso 5, la aplicación no logra comunicarse con la API. 2. La aplicación informa que no se pudo establecer comunicación con el servidor. 3. No se crea ninguna partida. 4. El anfitrión puede reintentar la operación.   **A5. El navegador no permite conservar la credencial**   1. En el paso 4, la aplicación detecta que no puede utilizar el almacenamiento requerido. 2. La aplicación no envía la solicitud de creación. 3. El sistema informa que el navegador debe permitir el almacenamiento local para recuperar la sesión. 4. El anfitrión permanece en la pantalla principal.   **A6. Fallo al almacenar la credencial después de crear la partida**   1. En el paso 16, la aplicación no logra almacenar la credencial. 2. La aplicación conserva temporalmente la credencial durante la sesión actual, si es posible. 3. El sistema advierte que la sesión del anfitrión podría perderse al recargar o cerrar el navegador. 4. El sistema permite copiar la credencial o recomienda crear una partida nueva, según la solución que se defina posteriormente. |
| **validaciones** | 1. El código público no puede estar vacío. 2. El código debe ser único entre las partidas activas. 3. La credencial del anfitrión debe ser diferente del código público. 4. La credencial debe generarse mediante un mecanismo seguro e impredecible. 5. La credencial no debe incluirse en la URL. 6. La credencial no debe mostrarse en el lobby público. 7. Deben seleccionarse exactamente cinco desafíos. 8. Los cinco desafíos deben estar activos. 9. No puede repetirse un desafío dentro de la misma partida. 10. El orden de los desafíos debe quedar establecido y no cambiar durante la partida. 11. La partida debe crearse únicamente en estado LOBBY. 12. La partida debe iniciar sin jugadores registrados. 13. La creación debe guardarse completamente o cancelarse completamente. 14. Una solicitud repetida por error no debería crear varias partidas de forma involuntaria mientras la primera solicitud continúa en proceso. 15. No deberá enviarse al frontend la respuesta correcta de los desafíos asignados. |
| **Mensaje de Sistema** | 1. Creación exitosa: “Partida creada correctamente. Comparte el código **code** con los jugadores.” 2. No existen suficientes desafíos: “No hay suficientes desafíos disponibles para crear la partida” 3. Error de comunicación: “No fue posible comunicarse con el servidor”. 4. Error al guardar: “No se pudo crear la partida. Inténtalo nuevamente.” 5. Almacenamiento local no disponible: “El navegador debe permitir el almacenamiento local para conservar la sesión del anfitrión.” 6. Credencial no almacenada: “La partida fue creada, pero no fue posible conservar la sesión del anfitrión. No recargues ni cierres esta página.” |
| **Salida de Sistema** | 1. Una nueva partida persistida. 2. Un código público único. 3. Una credencial privada de anfitrión. 4. Estado inicial LOBBY. 5. Cinco desafíos asignados sin repetición. 6. Orden definido de los desafíos. 7. Configuración de cinco rondas y treinta segundos por ronda. 8. Una sesión de anfitrión almacenada en el navegador. 9. Un lobby disponible para recibir jugadores. 10. Una pantalla que muestra el código público y la lista de participantes. |
