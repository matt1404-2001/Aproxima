| **CU-05** | **Iniciar partida** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. La partida debe encontrarse en estado LOBBY.  3. El anfitrión debe tener una credencial privada válida.  4. Deben existir al menos dos jugadores registrados.  5. La partida debe tener cinco desafíos asignados.  6. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Permitir que el anfitrión inicie la partida.  2. Impedir que un jugador inicie la partida.  3. Verificar que exista la cantidad mínima de participantes.  4. Activar la primera ronda.  5. Establecer el tiempo oficial de inicio y finalización.  6. Notificar a los jugadores que la partida comenzó. |
| **Descripción** | Este caso de uso permite que el anfitrión inicie una partida que se encuentra en el lobby.  Antes de iniciar, el sistema valida la credencial del anfitrión, el estado de la partida, la cantidad mínima de jugadores y la disponibilidad de los desafíos asignados.  Cuando las validaciones son correctas, el servidor activa la primera ronda, registra la hora oficial de inicio, calcula la hora límite y cambia el estado de la partida a RONDA\_ACTIVA.  Los jugadores detectan el cambio mediante polling y son dirigidos a la pantalla de la primera ronda. |
| **Entradas** | Entradas proporcionadas por el anfitrión:  - Selección de la opción “Iniciar partida”.  Entradas obtenidas de la sesión:  - Identificador de la partida.  - Credencial privada del anfitrión.  Entradas internas del sistema:  - Estado actual de la partida.  - Cantidad de jugadores registrados.  - Lista de desafíos asignados.  - Duración configurada de la ronda.  - Fecha y hora actual del servidor.  Disparador:  El caso de uso comienza cuando el anfitrión selecciona la opción “Iniciar partida” desde el lobby. |
| **Secuencia normal** | 1. El anfitrión consulta el lobby de la partida.  2. El sistema muestra la lista y la cantidad de jugadores registrados.  3. El sistema comprueba que existen al menos dos jugadores.  4. La aplicación habilita la opción “Iniciar partida”.  5. El anfitrión selecciona “Iniciar partida”.  6. La aplicación deshabilita temporalmente la opción para evitar solicitudes repetidas.  7. La aplicación envía al servidor el identificador de la partida y la credencial del anfitrión.  8. El servidor localiza la partida.  9. El servidor valida la credencial del anfitrión.  10. El servidor comprueba que la partida se encuentre en estado LOBBY.  11. El servidor verifica que existan al menos dos jugadores registrados.  12. El servidor verifica que la partida tenga cinco desafíos asignados.  13. El servidor identifica el primer desafío de la partida.  14. El servidor crea o activa la primera ronda.  15. El servidor registra la hora oficial de inicio de la ronda.  16. El servidor establece la hora de finalización treinta segundos después del inicio.  17. El servidor cambia el estado de la partida a RONDA\_ACTIVA.  18. El servidor guarda el cambio de estado y la información de la ronda.  19. El servidor devuelve la confirmación de inicio y la información pública de la primera ronda.  20. La aplicación dirige al anfitrión a la pantalla de la ronda activa.  21. Los clientes de los jugadores consultan periódicamente el estado de la partida.  22. Los jugadores detectan que la partida cambió a RONDA\_ACTIVA.  23. La aplicación dirige a cada jugador a la pantalla de la primera ronda.  24. El sistema muestra el enunciado, la unidad, el número de ronda y el tiempo restante.  25. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. No existen suficientes jugadores  1. En el paso 3, el sistema detecta que existen menos de dos jugadores.  2. La opción “Iniciar partida” permanece deshabilitada.  3. El sistema informa que se necesitan al menos dos participantes.  4. El anfitrión permanece en el lobby.  A2. La credencial del anfitrión no es válida  1. En el paso 9, el servidor no reconoce la credencial.  2. El servidor rechaza la solicitud.  3. La partida permanece en estado LOBBY.  4. El sistema informa que el anfitrión no tiene autorización.  5. La aplicación dirige al usuario a la pantalla principal.  A3. La partida ya fue iniciada  1. En el paso 10, el servidor detecta que la partida ya no se encuentra en estado LOBBY.  2. El servidor no crea otra ronda.  3. El servidor devuelve el estado actual de la partida.  4. La aplicación dirige al anfitrión a la pantalla correspondiente.  A4. La solicitud se envía varias veces  1. El anfitrión presiona repetidamente la opción “Iniciar partida”.  2. La aplicación bloquea nuevos envíos mientras la primera solicitud está pendiente.  3. Si otra solicitud llega al servidor, el servidor detecta que la partida ya fue iniciada.  4. El servidor no crea una segunda ronda.  5. El sistema devuelve el estado actual de la partida.  A5. No están disponibles los desafíos asignados  1. En el paso 12, el servidor detecta que la partida no tiene cinco desafíos válidos.  2. El servidor cancela el inicio.  3. La partida permanece en estado LOBBY.  4. El sistema informa que no fue posible preparar la partida.  5. El anfitrión puede crear una partida nueva.  A6. No se puede guardar el inicio de la partida  1. En el paso 18, ocurre un error al guardar los cambios.  2. El sistema cancela la operación completa.  3. La partida debe conservar su estado anterior.  4. No debe quedar una ronda parcialmente activa.  5. El sistema informa que no fue posible iniciar la partida.  A7. No se puede contactar con el servidor  1. En el paso 7, la aplicación no logra comunicarse con la API.  2. La aplicación conserva la sesión del anfitrión.  3. El sistema informa que no fue posible iniciar la partida.  4. El anfitrión puede reintentar la operación.  5. Antes de reintentar, la aplicación consulta el estado oficial de la partida.  A8. La respuesta del servidor se pierde después de iniciar  1. El servidor completa el inicio, pero la aplicación no recibe la confirmación.  2. La aplicación muestra un aviso de conexión.  3. La aplicación consulta nuevamente el estado de la partida.  4. El servidor devuelve el estado RONDA\_ACTIVA.  5. La aplicación dirige al anfitrión a la primera ronda.  6. No se crea una ronda adicional. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. La partida debe existir.  3. La credencial debe corresponder al anfitrión de la partida.  4. El código público no debe utilizarse para autorizar el inicio.  5. Un jugador no debe poder iniciar la partida.  6. La partida debe encontrarse en estado LOBBY.  7. Deben existir al menos dos jugadores registrados.  8. La cantidad de jugadores no puede superar el máximo de cuarenta.  9. La partida debe tener exactamente cinco desafíos asignados.  10. Los desafíos asignados no deben estar repetidos.  11. La primera ronda debe utilizar el primer desafío asignado.  12. La hora de inicio debe obtenerse del servidor.  13. La hora de finalización debe establecerse treinta segundos después del inicio.  14. La partida debe cambiar a RONDA\_ACTIVA.  15. El inicio debe guardarse completamente o cancelarse completamente.  16. Una solicitud repetida no debe crear varias rondas.  17. La respuesta correcta no debe enviarse a los clientes.  18. La ronda activa debe identificarse como la primera de cinco.  19. No deben admitirse nuevos jugadores después de iniciar la partida. |
| **Mensajes del sistema** | 1. Partida iniciada: “La partida ha comenzado”.  2. Cantidad insuficiente: “Se necesitan al menos 2 jugadores para iniciar”.  3. Sin autorización: “No tienes autorización para iniciar esta partida”.  4. Partida ya iniciada: “La partida ya se encuentra en curso”.  5. Desafíos no disponibles: “No fue posible preparar los desafíos de la partida”.  6. Error al guardar: “No fue posible iniciar la partida. Inténtalo nuevamente”.  7. Error de comunicación: “No fue posible comunicarse con el servidor”.  8. Conexión perdida: “Verificando el estado actual de la partida”.  9. Primera ronda: “Ronda 1 de 5”. |
| **Salida del sistema** | 1. Credencial del anfitrión validada.  2. Cantidad mínima de jugadores confirmada.  3. Primera ronda activada.  4. Primer desafío seleccionado.  5. Hora oficial de inicio registrada.  6. Hora oficial de finalización registrada.  7. Estado de la partida cambiado a RONDA\_ACTIVA.  8. Inicio de la partida persistido.  9. Pantalla de la primera ronda mostrada al anfitrión.  10. Cambio de estado disponible para los jugadores mediante polling.  11. Formulario de ingreso de nuevos jugadores bloqueado.  12. Respuesta correcta del desafío mantenida oculta. |
