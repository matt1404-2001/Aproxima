| **CU-11** | **Avanzar a la siguiente ronda** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. La partida debe encontrarse en estado RESULTADOS.  3. La ronda actual debe estar cerrada.  4. Los resultados de la ronda actual deben estar disponibles.  5. Debe quedar al menos un desafío pendiente.  6. El anfitrión debe tener una credencial privada válida.  7. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Permitir que el anfitrión controle el ritmo de la partida.  2. Mantener visibles los resultados hasta que el anfitrión decida continuar.  3. Activar la siguiente ronda.  4. Seleccionar el siguiente desafío asignado.  5. Establecer una nueva hora de inicio y finalización.  6. Notificar a los jugadores sobre el cambio de ronda.  7. Impedir que una solicitud repetida omita rondas. |
| **Descripción** | Este caso de uso permite que el anfitrión avance manualmente desde los resultados de una ronda hacia la siguiente.  El sistema valida la identidad del anfitrión, el estado de la partida y la existencia de un desafío pendiente. Después activa la nueva ronda, establece su tiempo oficial y cambia el estado de la partida a RONDA\_ACTIVA.  Los jugadores detectan el cambio mediante polling. El sistema no avanza automáticamente, aunque todos los resultados estén disponibles. |
| **Entradas** | Entradas proporcionadas por el anfitrión:  - Selección de la opción “Siguiente”.  Entradas obtenidas de la sesión:  - Identificador de la partida.  - Credencial privada del anfitrión.  - Identificador de la ronda actual.  Entradas internas del sistema:  - Estado actual de la partida.  - Número de la ronda finalizada.  - Cantidad total de rondas.  - Orden de los desafíos asignados.  - Siguiente desafío pendiente.  - Duración configurada de la ronda.  - Fecha y hora actual del servidor.  Disparador:  El caso de uso comienza cuando el anfitrión selecciona la opción “Siguiente” desde la pantalla de resultados. |
| **Secuencia normal** | 1. El anfitrión consulta los resultados de la ronda finalizada.  2. El sistema muestra la opción “Siguiente”.  3. El anfitrión decide continuar con la partida.  4. El anfitrión selecciona la opción “Siguiente”.  5. La aplicación deshabilita temporalmente la opción.  6. La aplicación obtiene el identificador de la partida.  7. La aplicación obtiene el identificador de la ronda actual.  8. La aplicación obtiene la credencial privada del anfitrión.  9. La aplicación envía al servidor la solicitud para avanzar.  10. El servidor localiza la partida.  11. El servidor valida la credencial del anfitrión.  12. El servidor comprueba que la partida se encuentre en estado RESULTADOS.  13. El servidor comprueba que la ronda actual esté cerrada.  14. El servidor comprueba que los resultados hayan sido calculados.  15. El servidor identifica el número de la ronda finalizada.  16. El servidor comprueba que no sea la quinta ronda.  17. El servidor identifica el siguiente desafío asignado.  18. El servidor calcula el número de la nueva ronda.  19. El servidor crea o activa la nueva ronda.  20. El servidor registra la hora oficial de inicio.  21. El servidor establece la hora oficial de finalización.  22. El servidor cambia el estado de la partida a RONDA\_ACTIVA.  23. El servidor guarda la nueva ronda y el cambio de estado.  24. El servidor devuelve la confirmación de avance.  25. El servidor devuelve la información pública de la nueva ronda.  26. La aplicación dirige al anfitrión a la nueva ronda.  27. Las aplicaciones de los jugadores consultan periódicamente el estado.  28. Los jugadores detectan el cambio a RONDA\_ACTIVA.  29. Las aplicaciones dirigen a los jugadores a la nueva ronda.  30. El sistema muestra el nuevo desafío.  31. El sistema inicia el contador visual.  32. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. La credencial del anfitrión no es válida  1. En el paso 11, el servidor no reconoce la credencial.  2. El servidor rechaza la solicitud.  3. La partida permanece en estado RESULTADOS.  4. El sistema informa que el usuario no tiene autorización.  5. No se crea una nueva ronda.  A2. Un jugador intenta avanzar  1. Un jugador envía una solicitud para avanzar.  2. El servidor determina que la credencial pertenece a un jugador.  3. El servidor rechaza la solicitud.  4. La partida permanece en estado RESULTADOS.  5. El sistema informa que solo el anfitrión puede continuar.  A3. La ronda todavía está activa  1. En el paso 12, el servidor detecta que la partida está en RONDA\_ACTIVA.  2. El servidor rechaza la solicitud.  3. La ronda actual continúa.  4. El sistema informa que la ronda todavía no ha terminado.  A4. Los resultados todavía no están disponibles  1. En el paso 14, el servidor detecta que los resultados no han terminado de calcularse.  2. El servidor rechaza temporalmente la solicitud.  3. La aplicación muestra un mensaje de espera.  4. El anfitrión puede intentarlo nuevamente cuando los resultados estén disponibles.  A5. La ronda finalizada es la quinta  1. En el paso 16, el servidor detecta que no quedan rondas pendientes.  2. El servidor no crea otra ronda.  3. La aplicación sustituye la opción “Siguiente” por “Finalizar partida”.  4. El anfitrión puede ejecutar el caso de uso de finalización.  5. La partida permanece en RESULTADOS hasta que el anfitrión finalice.  A6. No existe un desafío pendiente  1. En el paso 17, el servidor no encuentra el desafío correspondiente.  2. El servidor cancela la operación.  3. La partida permanece en RESULTADOS.  4. El sistema informa que no fue posible preparar la siguiente ronda.  5. No se modifica el número de ronda.  A7. La solicitud se envía varias veces  1. El anfitrión presiona repetidamente la opción “Siguiente”.  2. La aplicación bloquea nuevos envíos mientras existe una solicitud pendiente.  3. Si otra solicitud llega al servidor, el servidor detecta que la nueva ronda ya fue creada.  4. El servidor no crea otra ronda.  5. El servidor devuelve el estado actual de la partida.  A8. Dos solicitudes intentan avanzar simultáneamente  1. El servidor recibe dos solicitudes válidas casi al mismo tiempo.  2. El servidor permite que una solicitud realice la transición.  3. La segunda solicitud detecta que la partida ya está en RONDA\_ACTIVA.  4. La segunda solicitud no crea ni omite rondas.  5. Ambas aplicaciones reciben el estado actual.  A9. No se puede guardar la nueva ronda  1. En el paso 23, ocurre un error en la base de datos.  2. El servidor cancela la operación completa.  3. La partida conserva el estado RESULTADOS.  4. No debe quedar una ronda parcialmente creada.  5. El sistema informa que no fue posible avanzar.  A10. No se puede contactar con el servidor  1. En el paso 9, la aplicación no logra comunicarse con la API.  2. La aplicación conserva la sesión del anfitrión.  3. El sistema informa que no fue posible avanzar.  4. La aplicación consulta el estado oficial antes de permitir otro intento.  5. El anfitrión puede reintentar si la partida continúa en RESULTADOS.  A11. La respuesta del servidor se pierde después de avanzar  1. El servidor activa la nueva ronda, pero la aplicación no recibe la confirmación.  2. La aplicación muestra un aviso de conexión.  3. La aplicación consulta nuevamente el estado.  4. El servidor devuelve RONDA\_ACTIVA.  5. La aplicación dirige al anfitrión a la ronda activa.  6. No se crea otra ronda. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. El identificador de la ronda actual es obligatorio.  3. La credencial del anfitrión es obligatoria.  4. La partida debe existir.  5. La credencial debe pertenecer al anfitrión de la partida.  6. Un jugador no debe poder avanzar la partida.  7. La partida debe encontrarse en estado RESULTADOS.  8. La ronda actual debe estar cerrada.  9. Los resultados deben estar disponibles.  10. Debe existir una ronda pendiente.  11. El número de la nueva ronda debe ser consecutivo.  12. No debe omitirse ninguna ronda.  13. El siguiente desafío debe respetar el orden asignado.  14. Un desafío no debe utilizarse dos veces en la misma partida.  15. La hora de inicio debe obtenerse del servidor.  16. La hora de finalización debe establecerse treinta segundos después del inicio.  17. La partida debe cambiar a RONDA\_ACTIVA.  18. La transición debe guardarse completamente o cancelarse completamente.  19. Una solicitud repetida no debe crear varias rondas.  20. Solicitudes simultáneas no deben omitir rondas.  21. La respuesta correcta del nuevo desafío debe permanecer oculta.  22. Los jugadores deben comenzar la nueva ronda sin estimaciones registradas.  23. Los puntos acumulados de rondas anteriores no deben modificarse.  24. La nueva ronda no debe iniciarse automáticamente desde los resultados.  25. Después de la quinta ronda no debe crearse una sexta ronda. |
| **Mensajes del sistema** | 1. Avanzando: “Preparando la siguiente ronda”.  2. Nueva ronda: “La siguiente ronda ha comenzado”.  3. Sin autorización: “Solo el anfitrión puede avanzar la partida”.  4. Ronda activa: “La ronda actual todavía no ha terminado”.  5. Resultados en proceso: “Los resultados todavía están siendo preparados”.  6. Última ronda completada: “No quedan más rondas. Puedes finalizar la partida”.  7. Desafío no disponible: “No fue posible preparar la siguiente ronda”.  8. Solicitud repetida: “La partida ya avanzó a la siguiente ronda”.  9. Error al guardar: “No fue posible avanzar. Inténtalo nuevamente”.  10. Error de comunicación: “No fue posible comunicarse con el servidor”.  11. Verificando estado: “Verificando el estado actual de la partida”.  12. Progreso: “Ronda 2 de 5”. |
| **Salida del sistema** | 1. Credencial del anfitrión validada.  2. Ronda anterior confirmada como cerrada.  3. Nueva ronda creada o activada.  4. Número de ronda incrementado.  5. Siguiente desafío asignado.  6. Hora oficial de inicio registrada.  7. Hora oficial de finalización registrada.  8. Estado cambiado a RONDA\_ACTIVA.  9. Nueva ronda persistida.  10. Formularios de respuesta disponibles para los jugadores.  11. Contadores visuales iniciados.  12. Cambio de estado disponible mediante polling.  13. Resultados anteriores conservados.  14. Ranking acumulado conservado.  15. Respuesta correcta del nuevo desafío mantenida oculta. |
