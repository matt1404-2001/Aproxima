| **CU-02** | **Ingresar a una partida** |
| **Fecha de creación** | 26/09/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Jugador | Sistema |
| **Requisitos previos** | 1. El jugador debe tener acceso a la aplicación web. 2. El jugador debe haber recibido un código de partida. 3. La API y la base de datos deben estar disponibles. 4. La partida debe existir y encontrarse en estado LOBBY. 5. La partida debe tener espacio disponible. 6. El navegador debe permitir almacenar la credencial del jugador. |
| **Objetivos asociados** | 1. Permitir que una persona ingrese a una partida sin crear una cuenta. 2. Validar el código proporcionado por el jugador. 3. Registrar un nombre visible y único dentro de la partida. 4. Generar una credencial privada que identifique al jugador. 5. Incorporar al jugador al lobby. 6. Actualizar la lista de participantes. |
| **Descripción** | Este caso de uso permite que una persona ingrese como jugador a una partida de Estimate Arena utilizando el código público compartido por el anfitrión y un nombre visible.  El jugador no necesita registrarse ni proporcionar contraseña o información personal adicional. El sistema verifica que la partida exista, permanezca en el lobby, tenga capacidad y no contenga otro participante con el mismo nombre.  Cuando la solicitud es válida, el sistema registra al jugador, genera una credencial privada para reconocerlo después de una recarga y lo dirige al lobby de la partida. |
| **Entradas** | **Entradas proporcionadas por el jugador**:  - Código público de la partida.  - Nombre visible del jugador.  - Selección de la opción “Ingresar”.  **Entradas internas del sistema:**  - Estado actual de la partida.  - Cantidad actual de jugadores.  - Cantidad máxima de jugadores.  - Nombres registrados en la partida.  - Fecha y hora actual del servidor.  **Disparador**:  El caso de uso comienza cuando el jugador selecciona la opción “Ingresar a partida” desde la pantalla principal. |
| **Secuencia normal** | 1. El jugador accede a la pantalla principal de Estimate Arena. 2. El sistema muestra las opciones “Crear partida” e “Ingresar a partida”. 3. El jugador selecciona “Ingresar a partida”. 4. El sistema muestra un formulario para ingresar el código y el nombre. 5. El jugador introduce el código recibido del anfitrión. 6. El jugador introduce el nombre que desea utilizar. 7. La aplicación elimina los espacios exteriores de ambos valores. 8. La aplicación comprueba que el código y el nombre tengan un formato válido. 9. La aplicación comprueba que puede almacenar la credencial del jugador. 10. El jugador selecciona la opción “Ingresar”. 11. La aplicación envía al servidor el código y el nombre normalizado. 12. El servidor localiza la partida asociada con el código. 13. El servidor comprueba que la partida se encuentre en estado LOBBY. 14. El servidor comprueba que la partida no haya alcanzado el máximo de cuarenta jugadores. 15. El servidor valida que el nombre tenga entre dos y veinte caracteres visibles. 16. El servidor comprueba que el nombre no esté siendo utilizado en la partida, sin distinguir mayúsculas y minúsculas. 17. El servidor genera una credencial privada y segura para el jugador. 18. El servidor registra al jugador dentro de la partida. 19. El servidor guarda la participación. 20. El servidor devuelve la información pública de la partida y la credencial privada. 21. La aplicación almacena localmente la credencial del jugador. 22. La aplicación dirige al jugador al lobby. 23. El sistema muestra el código, el estado de espera y la lista actualizada de participantes. 24. La aplicación comienza a consultar periódicamente el estado de la partida. 25. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. El código o el nombre están vacíos   1. 1. En el paso 8, la aplicación detecta que falta un dato obligatorio. 2. 2. La aplicación no envía la solicitud al servidor. 3. 3. El sistema señala el campo que debe completarse. 4. 4. El jugador permanece en el formulario.   A2. El código no corresponde a una partida   1. En el paso 12, el servidor no encuentra una partida asociada con el código. 2. El servidor rechaza la solicitud. 3. El sistema informa que no se encontró la partida. 4. El jugador puede corregir el código e intentarlo nuevamente.   A3. La partida ya comenzó o finalizó   1. En el paso 13, el servidor detecta que la partida no se encuentra en estado LOBBY. 2. El servidor rechaza el ingreso. 3. El sistema informa que la partida ya no admite nuevos jugadores. 4. El jugador permanece en la pantalla de ingreso.   A4. La partida está llena   1. En el paso 14, el servidor detecta que existen cuarenta jugadores registrados. 2. El servidor rechaza el ingreso. 3. El sistema informa que la partida alcanzó su capacidad máxima.   **A5. El nombre no es válido**   1. En el paso 15, el servidor detecta que el nombre no cumple la longitud permitida. 2. El servidor rechaza la solicitud. 3. El sistema solicita que se introduzca un nombre válido.   **A6. El nombre ya está ocupado**   1. En el paso 16, el servidor encuentra otro jugador con el mismo nombre normalizado. 2. El servidor rechaza la solicitud. 3. El sistema informa que el nombre ya está en uso. 4. El jugador puede elegir otro nombre e intentarlo nuevamente.   **A7. No se puede contactar con el servidor**   1. En el paso 11, la aplicación no logra comunicarse con la API. 2. La aplicación informa que no fue posible establecer comunicación. 3. El jugador permanece en el formulario. 4. El jugador puede reintentar la operación.   **A8. No se puede guardar al jugador**   1. En el paso 19, ocurre un error antes de confirmar el registro. 2. El sistema cancela la operación completa. 3. No debe quedar un jugador parcialmente registrado. 4. El sistema informa que no fue posible ingresar a la partida.   **A9. El navegador no permite conservar la credencial**   1. En el paso 9, la aplicación detecta que no puede utilizar el almacenamiento requerido. 2. 2. La aplicación no envía la solicitud de ingreso. 3. 3. El sistema informa que debe permitirse el almacenamiento local. 4. 4. El jugador permanece en el formulario. |
| **validaciones** | 1. El código de partida es obligatorio. 2. Deben eliminarse los espacios exteriores del código. 3. El código debe corresponder a una partida existente. 4. La partida debe encontrarse en estado LOBBY. 5. La partida debe tener menos de cuarenta jugadores. 6. El nombre es obligatorio. 7. Deben eliminarse los espacios exteriores del nombre. 8. El nombre debe contener entre dos y veinte caracteres visibles. 9. El nombre no puede estar formado únicamente por espacios. 10. El nombre debe ser único dentro de la partida sin distinguir mayúsculas y minúsculas. 11. El nombre debe almacenarse y mostrarse como texto, sin ejecutar HTML o scripts. 12. La credencial debe generarse mediante un mecanismo seguro e impredecible. 13. La credencial del jugador debe ser diferente del código público. 14. La credencial no debe incluirse en la URL. 15. La credencial no debe mostrarse a otros participantes. 16. El registro del jugador debe guardarse completamente o cancelarse completamente. 17. El ingreso no debe revelar desafíos ni respuestas correctas. |
| **Mensaje de Sistema** | 1. Ingreso exitoso: “Te uniste a la partida. Esperando a que el anfitrión inicie”. 2. Datos incompletos: “Ingresa el código de la partida y tu nombre”. 3. Partida inexistente: “No encontramos una partida con ese código”. 4. Partida no disponible: “La partida ya comenzó o finalizó y no admite nuevos jugadores”. 5. Partida llena: “La partida alcanzó el máximo de jugadores”. 6. Nombre inválido: “El nombre debe tener entre 2 y 20 caracteres”. 7. Nombre ocupado: “Ese nombre ya está en uso. Elige otro”. 8. Error de comunicación: “No fue posible comunicarse con el servidor”. 9. Error al guardar: “No fue posible ingresar a la partida. Inténtalo nuevamente”. 10. Almacenamiento no disponible: “El navegador debe permitir el almacenamiento local para conservar tu sesión”. |
| **Salida de Sistema** | 1. Un nuevo jugador registrado dentro de la partida. 2. Un nombre visible y único asociado con el jugador. 3. Una credencial privada de jugador. 4. Una sesión de jugador almacenada en el navegador. 5. La lista de participantes actualizada. 6. La información pública de la partida disponible. 7. El jugador ubicado en el lobby. 8. La consulta periódica del estado de la partida iniciada. |
