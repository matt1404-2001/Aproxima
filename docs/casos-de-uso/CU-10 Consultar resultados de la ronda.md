| **CU-10** | **Consultar resultados de la ronda** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | Jugador | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. La ronda debe haber finalizado.  3. La partida debe encontrarse en estado RESULTADOS.  4. Los resultados de la ronda deben haber sido calculados.  5. El usuario debe tener una credencial válida.  6. El jugador debe estar registrado en la partida.  7. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Mostrar la respuesta correcta del desafío.  2. Mostrar el resultado individual del jugador.  3. Mostrar la diferencia entre la estimación y la respuesta correcta.  4. Mostrar los puntos obtenidos.  5. Mostrar las estadísticas colectivas de la ronda.  6. Informar cuántos jugadores respondieron.  7. Permitir que el anfitrión decida cuándo avanzar.  8. Mantener a los jugadores en la pantalla de resultados hasta que el anfitrión continúe. |
| **Descripción** | Este caso de uso permite que el anfitrión y los jugadores consulten los resultados de una ronda cerrada.  El sistema muestra la respuesta correcta y las estadísticas calculadas utilizando únicamente estimaciones válidas. Cada jugador puede consultar su propia estimación, la diferencia obtenida y los puntos asignados.  El anfitrión puede revisar los resultados y decidir cuándo avanzar. Los jugadores permanecen esperando mientras la partida continúe en estado RESULTADOS. |
| **Entradas** | Entradas obtenidas de la sesión:  - Identificador de la partida.  - Identificador de la ronda.  - Credencial privada del anfitrión o jugador.  - Rol del usuario.  Entradas internas del sistema:  - Estado actual de la partida.  - Respuesta correcta.  - Estimaciones válidas.  - Resultado individual de cada jugador.  - Diferencias calculadas.  - Puntos obtenidos.  - Estimación mínima.  - Promedio de las estimaciones.  - Estimación máxima.  - Cantidad de respuestas.  - Cantidad total de jugadores.  - Explicación o fuente del desafío, si se implementa.  Disparador:  El caso de uso comienza cuando la aplicación detecta que la partida cambió al estado RESULTADOS. |
| **Secuencia normal** | 1. La aplicación detecta que la partida se encuentra en estado RESULTADOS.  2. La aplicación obtiene el identificador de la partida.  3. La aplicación obtiene el identificador de la ronda.  4. La aplicación obtiene la credencial almacenada.  5. La aplicación solicita al servidor los resultados de la ronda.  6. El servidor localiza la partida.  7. El servidor valida la credencial recibida.  8. El servidor identifica el rol del usuario.  9. El servidor comprueba que el usuario pertenezca a la partida.  10. El servidor consulta el estado actual de la partida.  11. El servidor comprueba que la partida se encuentre en estado RESULTADOS.  12. El servidor identifica la ronda que acaba de finalizar.  13. El servidor obtiene la respuesta correcta.  14. El servidor obtiene la cantidad de respuestas válidas.  15. El servidor obtiene la estimación mínima.  16. El servidor obtiene el promedio de las estimaciones.  17. El servidor obtiene la estimación máxima.  18. El servidor identifica si el usuario es un jugador.  19. El servidor obtiene la estimación del jugador.  20. El servidor obtiene la diferencia calculada para el jugador.  21. El servidor obtiene los puntos asignados al jugador.  22. El servidor prepara la información permitida para el usuario.  23. El servidor devuelve los resultados de la ronda.  24. La aplicación muestra el número de la ronda finalizada.  25. La aplicación muestra el enunciado del desafío.  26. La aplicación muestra la respuesta correcta.  27. La aplicación muestra la cantidad de jugadores que respondieron.  28. La aplicación muestra la estimación mínima.  29. La aplicación muestra el promedio.  30. La aplicación muestra la estimación máxima.  31. La aplicación muestra al jugador su estimación.  32. La aplicación muestra al jugador la diferencia obtenida.  33. La aplicación muestra al jugador los puntos obtenidos.  34. La aplicación muestra la explicación o fuente del desafío cuando esté disponible.  35. Si el usuario es el anfitrión, la aplicación muestra la opción para avanzar.  36. Si el usuario es un jugador, la aplicación muestra un mensaje de espera.  37. La aplicación continúa consultando periódicamente el estado de la partida.  38. El caso de uso finaliza cuando el anfitrión avanza o finaliza la partida. |
| **Secuencias alternativas y excepciones** | A1. El jugador no respondió  1. En el paso 19, el servidor determina que no existe una estimación del jugador.  2. El servidor indica que el jugador no respondió.  3. El servidor devuelve cero puntos para esa ronda.  4. La aplicación muestra el mensaje “No enviaste una estimación”.  5. La aplicación no muestra una diferencia individual.  A2. Ningún jugador respondió  1. En el paso 14, el servidor determina que no existen estimaciones válidas.  2. El servidor devuelve cero respuestas.  3. El servidor no devuelve mínimo, promedio ni máximo.  4. La aplicación muestra “Sin respuestas”.  5. La aplicación muestra la respuesta correcta.  6. Todos los jugadores reciben cero puntos.  A3. Solo respondió un jugador  1. El servidor obtiene una única estimación.  2. La estimación mínima corresponde al valor registrado.  3. El promedio corresponde al valor registrado.  4. La estimación máxima corresponde al valor registrado.  5. La aplicación muestra normalmente las estadísticas.  A4. Los resultados todavía están siendo calculados  1. En el paso 11, el servidor determina que el cierre todavía no terminó.  2. El servidor informa que los resultados aún no están disponibles.  3. La aplicación muestra un indicador de espera.  4. La aplicación programa una nueva consulta.  5. El usuario permanece en la pantalla de espera.  A5. El usuario es el anfitrión  1. En el paso 18, el servidor identifica al usuario como anfitrión.  2. El servidor no busca una estimación personal.  3. El servidor devuelve los resultados generales.  4. La aplicación muestra las estadísticas.  5. La aplicación muestra la opción “Siguiente”.  6. La aplicación no muestra puntos personales del anfitrión.  A6. La ronda solicitada no es la ronda de resultados  1. En el paso 12, el servidor detecta que el identificador recibido está desactualizado.  2. El servidor devuelve la ronda actual.  3. La aplicación descarta la información anterior.  4. La aplicación solicita los resultados de la ronda vigente.  A7. La partida avanzó a otra ronda  1. En el paso 11, el servidor detecta que la partida se encuentra en RONDA\_ACTIVA.  2. El servidor no devuelve los resultados como estado actual.  3. El servidor devuelve la información pública de la nueva ronda.  4. La aplicación dirige al usuario a la ronda activa.  A8. La partida ya finalizó  1. En el paso 11, el servidor detecta el estado FINALIZADA.  2. El servidor devuelve la información final disponible.  3. La aplicación dirige al usuario al ranking final.  4. La aplicación detiene la consulta de resultados de la ronda anterior.  A9. La credencial no es válida  1. En el paso 7, el servidor no reconoce la credencial.  2. El servidor rechaza la solicitud.  3. La aplicación elimina la sesión inválida.  4. El sistema informa que no fue posible validar la sesión.  5. El usuario es dirigido a la pantalla principal.  A10. El usuario no pertenece a la partida  1. En el paso 9, el servidor determina que el usuario pertenece a otra partida.  2. El servidor rechaza la consulta.  3. El servidor no revela resultados.  4. El sistema informa que el usuario no tiene acceso.  A11. La partida no existe o expiró  1. En el paso 6, el servidor no encuentra la partida.  2. El servidor rechaza la consulta.  3. La aplicación elimina la información local asociada.  4. El sistema informa que la partida ya no está disponible.  5. El usuario es dirigido a la pantalla principal.  A12. No se puede contactar con el servidor  1. En el paso 5, la aplicación no logra comunicarse con la API.  2. La aplicación conserva la sesión.  3. La aplicación muestra un aviso de conexión.  4. La aplicación no inventa ni calcula resultados localmente.  5. La aplicación intenta consultar nuevamente. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. El identificador de la ronda es obligatorio.  3. La credencial del usuario es obligatoria.  4. La partida debe existir.  5. La ronda debe existir.  6. La ronda consultada debe corresponder con la ronda de resultados.  7. La credencial debe ser válida.  8. El usuario debe pertenecer a la partida.  9. La partida debe encontrarse en estado RESULTADOS.  10. La respuesta correcta solo puede mostrarse después del cierre.  11. Los resultados deben provenir del servidor.  12. El cliente no debe calcular ni modificar los puntos.  13. Las estadísticas deben utilizar únicamente estimaciones válidas.  14. Las estimaciones rechazadas no deben incluirse en las estadísticas.  15. Los jugadores sin respuesta deben recibir cero puntos.  16. Un jugador solo puede consultar su resultado individual.  17. El anfitrión puede consultar los resultados generales.  18. El anfitrión no debe recibir un resultado personal si no participa como jugador.  19. Si no existen respuestas, mínimo, promedio y máximo deben mostrarse como no disponibles.  20. Si existe una respuesta, mínimo, promedio y máximo pueden ser iguales.  21. La cantidad de respuestas no puede superar la cantidad de jugadores.  22. La opción para avanzar solo debe mostrarse al anfitrión.  23. Los jugadores no deben poder avanzar la partida.  24. La consulta de resultados no debe iniciar automáticamente otra ronda.  25. Una falla de conexión no debe eliminar la sesión.  26. El frontend no debe mostrar información almacenada de otra ronda como resultado actual. |
| **Mensajes del sistema** | 1. Resultados disponibles: “Resultados de la ronda”.  2. Respuesta correcta: “La respuesta correcta es”.  3. Estimación personal: “Tu estimación fue”.  4. Diferencia obtenida: “Tu diferencia fue”.  5. Puntos obtenidos: “Obtuviste puntos en esta ronda”.  6. Sin respuesta personal: “No enviaste una estimación”.  7. Sin respuestas: “Ningún jugador respondió esta ronda”.  8. Esperando al anfitrión: “Esperando a que el anfitrión continúe”.  9. Resultados en proceso: “Preparando los resultados”.  10. Ronda actualizada: “La partida avanzó a la siguiente ronda”.  11. Partida finalizada: “La partida ha finalizado”.  12. Sesión inválida: “No fue posible validar tu sesión”.  13. Sin autorización: “No tienes acceso a estos resultados”.  14. Error de comunicación: “No fue posible obtener los resultados”. |
| **Salida del sistema** | 1. Número de la ronda finalizada.  2. Enunciado del desafío mostrado.  3. Respuesta correcta mostrada.  4. Cantidad de respuestas mostrada.  5. Estimación mínima mostrada.  6. Promedio de las estimaciones mostrado.  7. Estimación máxima mostrada.  8. Estimación individual mostrada cuando corresponda.  9. Diferencia individual mostrada cuando corresponda.  10. Puntos individuales mostrados cuando corresponda.  11. Mensaje de falta de respuesta mostrado cuando corresponda.  12. Explicación o fuente mostrada cuando esté disponible.  13. Opción para avanzar disponible para el anfitrión.  14. Mensaje de espera mostrado a los jugadores.  15. Polling del estado de la partida activo. |
