| **CU-13** | **Finalizar partida** |
| **Fecha de creación** | 03/10/2026 |
| **Versión** | 1 |
| **Autor** | Mathiew Lopez |
| **Actores** | Anfitrión | Sistema |
| **Requisitos previos** | 1. La partida debe existir.  2. La quinta ronda debe haber finalizado.  3. La partida debe encontrarse en estado RESULTADOS.  4. Los resultados de la quinta ronda deben estar calculados.  5. El ranking acumulado debe estar actualizado.  6. El anfitrión debe tener una credencial privada válida.  7. La API y la base de datos deben estar disponibles. |
| **Objetivos asociados** | 1. Permitir que el anfitrión finalice la partida.  2. Impedir la creación de una sexta ronda.  3. Cambiar la partida al estado FINALIZADA.  4. Confirmar la clasificación definitiva.  5. Mostrar el ranking final a todos los participantes.  6. Bloquear nuevas estimaciones y cambios de ronda.  7. Conservar los resultados de la partida. |
| **Descripción** | Este caso de uso permite que el anfitrión finalice la partida después de revisar los resultados de la quinta ronda.  El servidor valida la credencial del anfitrión, comprueba que no queden rondas pendientes y cambia el estado de la partida a FINALIZADA.  Después de finalizar, el ranking acumulado se considera definitivo. Los jugadores detectan el cambio mediante polling y son dirigidos a la pantalla de clasificación final.  Una partida finalizada no puede reiniciarse ni aceptar nuevas estimaciones. Para jugar nuevamente, el anfitrión deberá crear otra partida. |
| **Entradas** | Entradas proporcionadas por el anfitrión:  - Selección de la opción “Finalizar partida”.  Entradas obtenidas de la sesión:  - Identificador de la partida.  - Credencial privada del anfitrión.  - Identificador de la quinta ronda.  Entradas internas del sistema:  - Estado actual de la partida.  - Número de la ronda finalizada.  - Resultados de la quinta ronda.  - Puntuaciones acumuladas.  - Ranking actualizado.  - Fecha y hora actual del servidor.  Disparador:  El caso de uso comienza cuando el anfitrión selecciona la opción “Finalizar partida” después de revisar los resultados de la quinta ronda. |
| **Secuencia normal** | 1. El anfitrión consulta los resultados de la quinta ronda.  2. El sistema determina que no quedan desafíos pendientes.  3. La aplicación muestra la opción “Finalizar partida”.  4. El anfitrión selecciona la opción “Finalizar partida”.  5. La aplicación deshabilita temporalmente la opción.  6. La aplicación obtiene el identificador de la partida.  7. La aplicación obtiene el identificador de la quinta ronda.  8. La aplicación obtiene la credencial privada del anfitrión.  9. La aplicación envía al servidor la solicitud de finalización.  10. El servidor localiza la partida.  11. El servidor valida la credencial del anfitrión.  12. El servidor comprueba que la partida se encuentre en estado RESULTADOS.  13. El servidor comprueba que la ronda actual sea la quinta.  14. El servidor comprueba que la quinta ronda esté cerrada.  15. El servidor comprueba que los resultados estén almacenados.  16. El servidor comprueba que las puntuaciones acumuladas estén actualizadas.  17. El servidor obtiene el ranking acumulado.  18. El servidor ordena el ranking de mayor a menor puntuación.  19. El servidor confirma las posiciones compartidas por jugadores empatados.  20. El servidor marca el ranking como final.  21. El servidor cambia el estado de la partida a FINALIZADA.  22. El servidor registra la hora oficial de finalización.  23. El servidor guarda el nuevo estado.  24. El servidor devuelve la confirmación de finalización.  25. El servidor devuelve el ranking final.  26. La aplicación dirige al anfitrión a la pantalla final.  27. Las aplicaciones de los jugadores consultan periódicamente el estado.  28. Los jugadores detectan que la partida cambió a FINALIZADA.  29. Las aplicaciones dirigen a los jugadores al ranking final.  30. El sistema muestra la clasificación definitiva.  31. El sistema bloquea las acciones de juego.  32. El caso de uso finaliza correctamente. |
| **Secuencias alternativas y excepciones** | A1. La credencial del anfitrión no es válida  1. En el paso 11, el servidor no reconoce la credencial.  2. El servidor rechaza la solicitud.  3. La partida permanece en estado RESULTADOS.  4. El sistema informa que el usuario no tiene autorización.  5. La partida no se finaliza.  A2. Un jugador intenta finalizar la partida  1. Un jugador envía una solicitud de finalización.  2. El servidor determina que la credencial pertenece a un jugador.  3. El servidor rechaza la solicitud.  4. La partida conserva su estado.  5. El sistema informa que solo el anfitrión puede finalizar.  A3. La partida todavía tiene rondas pendientes  1. En el paso 13, el servidor detecta que la ronda actual no es la quinta.  2. El servidor rechaza la finalización.  3. La partida permanece en RESULTADOS.  4. El sistema informa que todavía quedan rondas por jugar.  5. El anfitrión puede avanzar a la siguiente ronda.  A4. La quinta ronda continúa activa  1. En el paso 12, el servidor detecta el estado RONDA\_ACTIVA.  2. El servidor rechaza la finalización.  3. La ronda continúa hasta que se cumpla una condición de cierre.  4. El sistema informa que la ronda todavía no ha terminado.  A5. Los resultados todavía están siendo calculados  1. En el paso 15, el servidor determina que los resultados no están disponibles.  2. El servidor rechaza temporalmente la finalización.  3. La aplicación muestra un mensaje de espera.  4. El anfitrión puede intentarlo nuevamente cuando termine el cálculo.  A6. El ranking no está actualizado  1. En el paso 16, el servidor detecta puntuaciones pendientes.  2. El servidor intenta completar el cálculo.  3. Si el cálculo termina correctamente, el flujo continúa desde el paso 17.  4. Si el cálculo falla, la partida permanece en RESULTADOS.  5. El sistema informa que no fue posible preparar el ranking final.  A7. La partida ya estaba finalizada  1. En el paso 12, el servidor detecta el estado FINALIZADA.  2. El servidor no repite la transición.  3. El servidor devuelve el ranking final existente.  4. La aplicación dirige al anfitrión a la pantalla final.  5. No se modifican nuevamente los resultados.  A8. La solicitud se envía varias veces  1. El anfitrión presiona repetidamente la opción de finalización.  2. La aplicación bloquea nuevos envíos mientras la primera solicitud está pendiente.  3. Si otra solicitud llega al servidor, este detecta que la partida ya finalizó.  4. El servidor no duplica la operación.  5. El servidor devuelve el estado final existente.  A9. No se puede guardar la finalización  1. En el paso 23, ocurre un error en la base de datos.  2. El servidor cancela la transición.  3. La partida permanece en estado RESULTADOS.  4. El ranking todavía no se marca como definitivo.  5. El sistema informa que no fue posible finalizar la partida.  A10. No se puede contactar con el servidor  1. En el paso 9, la aplicación no logra comunicarse con la API.  2. La aplicación conserva la sesión del anfitrión.  3. El sistema informa que no fue posible finalizar la partida.  4. La aplicación consulta el estado oficial antes de permitir otro intento.  5. El anfitrión puede reintentar si la partida continúa en RESULTADOS.  A11. La respuesta del servidor se pierde después de finalizar  1. El servidor finaliza la partida, pero la aplicación no recibe la confirmación.  2. La aplicación muestra un aviso de conexión.  3. La aplicación consulta nuevamente el estado.  4. El servidor devuelve el estado FINALIZADA.  5. El servidor devuelve el ranking final.  6. La aplicación dirige al anfitrión a la pantalla final.  A12. La partida no existe o expiró  1. En el paso 10, el servidor no encuentra la partida.  2. El servidor rechaza la solicitud.  3. La aplicación elimina la información local asociada.  4. El sistema informa que la partida ya no está disponible.  5. El usuario es dirigido a la pantalla principal. |
| **Validaciones** | 1. El identificador de la partida es obligatorio.  2. El identificador de la quinta ronda es obligatorio.  3. La credencial del anfitrión es obligatoria.  4. La partida debe existir.  5. La credencial debe pertenecer al anfitrión.  6. Un jugador no debe poder finalizar la partida.  7. La partida debe encontrarse en estado RESULTADOS.  8. La ronda vigente debe ser la quinta.  9. La quinta ronda debe estar cerrada.  10. Los resultados de la quinta ronda deben estar completos.  11. Las puntuaciones acumuladas deben estar actualizadas.  12. Todos los jugadores deben estar incluidos en el ranking.  13. Los jugadores sin respuesta deben conservarse en la clasificación.  14. Los jugadores empatados deben compartir posición.  15. El ranking debe ordenarse de mayor a menor puntuación.  16. El ranking debe marcarse como final.  17. La hora de finalización debe obtenerse del servidor.  18. La partida debe cambiar a FINALIZADA.  19. La transición debe guardarse completamente o cancelarse completamente.  20. Una solicitud repetida no debe duplicar la finalización.  21. No debe crearse una sexta ronda.  22. No deben aceptarse nuevas estimaciones.  23. No deben permitirse nuevos jugadores.  24. No debe permitirse avanzar a otra ronda.  25. Los resultados existentes no deben modificarse.  26. Una partida finalizada no debe reiniciarse.  27. El anfitrión debe crear una partida nueva para volver a jugar.  28. El ranking final debe provenir del servidor.  29. Una falla de conexión no debe eliminar la sesión.  30. Los jugadores deben poder consultar el resultado final mientras la partida se conserve. |

Ranking final: “Clasificación final”.  4. Sin autorización: “Solo el anfitrión puede finalizar la partida”.  5. Rondas pendientes: “Todavía quedan rondas por jugar”.  6. Ronda activa: “La ronda actual todavía no ha terminado”.  7. Resultados en proceso: “Los resultados todavía están siendo preparados”.  8. Ranking en proceso: “Preparando la clasificación final”.  9. Partida ya finalizada: “La partida ya había finalizado”.  10. Error al guardar: “No fue posible finalizar la partida”.  11. Error de comunicación: “No fue posible comunicarse con el servidor”.  12. Verificando estado: “Verificando el estado actual de la partida”.  13. Partida no disponible: “La partida ya no está disponible”.  14. Nueva partida: “Crea una nueva partida para volver a jugar”. |
| **Salida del sistema** | 1. Credencial del anfitrión validada.  2. Quinta ronda confirmada como cerrada.  3. Resultados finales confirmados.  4. Puntuaciones acumuladas confirmadas.  5. Ranking ordenado.  6. Empates conservados.  7. Ranking marcado como final.  8. Estado cambiado a FINALIZADA.  9. Hora oficial de finalización almacenada.  10. Finalización persistida.  11. Ranking final mostrado al anfitrión.  12. Ranking final mostrado a los jugadores.  13. Formularios de estimación bloqueados.  14. Ingreso de nuevos jugadores bloqueado.  15. Avance de rondas bloqueado.  16. Resultados de la partida conservados. |
